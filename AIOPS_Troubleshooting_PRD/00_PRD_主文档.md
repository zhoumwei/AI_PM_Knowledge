## 1. 项目概述

> 本章背景调研详见 [01_AIOps行业调研报告.md](01_需求分析/01_AIOps行业调研报告.md)

### 1.1 背景

- 当前运维痛点
  - 告警风暴
  - MTTR 长
  - 专家经验难沉淀
- 行业趋势
  - **AIOps 1.0 → 2.0 范式迁移**：从"统计学习/机器学习的算法辅助"演进到"LLM + Agent 的自主智能"，补齐"识别异常 → 处置决策"中间的理解与决策空白
  - **2026 三大趋势**：①Agent 化（自主感知→分析→决策→执行）②多模态（日志+指标+Trace+拓扑）③私有化（Qwen3 / DeepSeek-Coder V3 本地化微调）
  - LLM 落地运维场景的成熟度（CCF 2023 起引入 LLM，2024 确立 RAG 范式，2025 确立 Agent 范式）
- 公司内部契机
  - 已有数据基础
  - 业务诉求等

### 1.2 问题陈述

> 用一句话描述我们要解决的核心问题。

**问题陈述**：告警发生后，根因定位依赖人工跨团队排查、经验难以沉淀，导致 MTTR 过长。我们用 LLM + Agent + RAG 构建"告警→归因→处置→复盘"的端到端智能闭环，将故障排查从"人工拉群"升级为"Agent 自主推理 + 人工确认"。

### 1.3 产品定位

> 产品是什么、给谁用、解决什么问题、与现有方案的差异。

| 维度    | 描述                             |
| ----- | ------------------------------ |
| 产品是什么 | 基于 LLM + RAG + Agent 的智能运维排查助手，遵循 AgentOps 范式 |
| 目标用户  | SRE、值班运维工程师、开发负责人              |
| 核心价值  | 告警自动归因 + 根因定位 + 修复建议）          |
| 差异化   | 结合企业历史故障知识库与实时拓扑；多 Agent 协作 + SOP 流程约束推理路径 |

### 1.4 价值主张

> 对用户和公司的价值。行业基线参考：头部 AIOps 实践 MTTR 缩短 90%+、运维人工成本降低 50-70%。

- 用户价值：减少排查时间、降低排障门槛
- 公司价值：降低故障损失、沉淀运维知识

## 2. 项目目标与成功标准

### 2.1 业务目标

> 项目要达成的业务结果，符合 SMART 原则。行业基线参考：头部实践 MTTR 缩短 90%+、运维人工成本降低 50-70%。

| 目标           | 当前基线 | 目标值 | 衡量方式 |
| ------------ | ---- | --- | ---- |
| MTTR（平均恢复时间） | TBD  | 较基线缩短 ≥ 50%（分阶段目标 90%） | 故障工单时间戳差值 |
| 告警自动归因准确率    | TBD  | Top-1 ≥ 60%，Top-3 召回率 ≥ 85% | 标注数据集评测 |
| 修复建议采纳率      | TBD  | ≥ 40%（首期） | 用户埋点统计 |
| Token 成本控制 | - | 单次归因 ≤ TBD tokens | 监控仪表盘 |

### 2.2 成功标准（上线门槛）

> 满足什么条件可以全量上线。

- 核心指标达标线：归因 Top-3 召回率 ≥ 85%、修复建议采纳率 ≥ 40%、MTTR 改善 ≥ 30%
- 安全/合规要求：高危操作 100% 人工确认、审计日志完整、数据脱敏生效
- 灰度范围与时长：单业务线灰度 ≥ 4 周，无 P0 事故

### 2.3 非目标（本期不做）

> 明确边界，避免范围蔓延。参考 LLM4AIOps 综述五层自动化：L1 辅助提问 / L2 方案生成 / L3 命令推荐 / L4 脚本生成 / L5 自动执行。

- 不做全自动修复（仅做到 L3 命令推荐，L4 脚本生成与 L5 自动执行本期不做，需人工确认）
- 不做告警产生环节的优化（仅消费告警，不替代监控）
- 不做多模态原始数据处理（图像/视频告警暂不支持）

## 3. 用户与场景分析

> 运维工作的三类语义任务（调研结论）：①读（告警/日志/工单）②推理（串联因果链）③表达（复盘/脚本），恰好对应 LLM 的核心能力。

### 3.1 用户画像

| 角色        | 职责        | 痛点             | 期望             |
| --------- | --------- | -------------- | -------------- |
| SRE 值班工程师 | 响应告警、初步排查 | 告警风暴、信息分散、夜间疲劳 | 快速定位根因、给出下一步动作 |
| 应用开发负责人   | 深度排查、修复   | 不熟悉基础设施、跨团队协作难 | 关联应用变更与基础设施异常  |
| 运维主管      | 复盘、知识沉淀   | 经验难传承、复盘耗时     | 自动沉淀故障案例与 SOP  |

### 3.2 核心使用场景

> 用 User Story 形式描述。

**场景 1：告警归因（最高频）**

- **触发**：生产告警产生
- **用户**：SRE 值班工程师
- **故事**：作为 SRE，当告警发生时，我希望系统能自动关联相关日志/指标/拓扑/变更，并在 1 分钟内给出可能的根因排序，以便我快速决策。
- **验收**：TBD

**场景 2：根因深挖**

- **触发**：归因结果不确定或需验证
- **用户**：SRE / 开发负责人
- **故事**：作为排查人员，我希望通过对话方式让 Agent 执行进一步排查（查日志、跑诊断命令、对比历史），逐步收敛根因。
- **验收**：TBD

**场景 3：修复建议与执行**

- **触发**：根因定位后
- **用户**：SRE
- **故事**：作为 SRE，我希望系统给出修复建议（含风险评估），确认后可自动执行低风险操作，高危操作需二次确认。
- **验收**：TBD

**场景 4：故障复盘与知识沉淀**

- **触发**：故障恢复后
- **用户**：运维主管
- **故事**：作为主管，我希望系统自动生成复盘报告并将本次故障沉淀为知识库案例，供未来检索。
- **验收**：TBD

告警产生 → [AI 归因] → 人工确认 → [AI 深挖] → 根因定位

## 5. Agent 架构与核心能力

> 参考知识库 [02\_Agent架构设计.md](../07_AI%20Agent产品设计/02_Agent架构设计.md)

### 5.1 Agent 角色划分

> 参考调研结论：CCF 2025 赛道一冠军方案采用多 Agent 协作（MainAgent + ObAgent + JudgeAgent）+ SOP 流程约束。

| Agent    | 职责        | 对应 CCF 角色 | 输入         | 输出          |
| -------- | --------- | ----------- | ---------- | ----------- |
| 归因 Agent | 告警 → 根因候选 | ObAgent     | 告警事件       | 根因列表 + 证据   |
| 深挖 Agent | 多轮对话排查    | -           | 用户问题 + 上下文 | 诊断结果 + 下一步  |
| 修复 Agent | 根因 → 修复方案 | -           | 根因 + 风险偏好  | 修复步骤 + 风险评估 |
| 协调 Agent | 任务路由与编排   | MainAgent   | 用户意图       | 分发给子 Agent  |
| 评审 Agent | 判断是否找到根因  | JudgeAgent  | 候选根因 + 证据 | 是否收敛/继续深挖   |

### 5.2 工具能力（Function Calling）

| 工具     | 功能       | 风险等级 | 是否需人工确认 |
| ------ | -------- | ---- | ------- |
| 查询日志   | 检索日志关键字  | 低    | 否       |
| 查询指标   | 拉取监控时序数据 | 低    | 否       |
| 查询变更   | 检索近期发布记录 | 低    | 否       |
| 查询拓扑   | 获取依赖关系   | 低    | 否       |
| 执行诊断命令 | 跑只读诊断脚本  | 中    | 否       |
| 执行修复操作 | 重启/回滚/扩容 | 高    | 是       |
| TBD    | TBD      | TBD  | TBD     |

| 知识类型   | 来源     | 更新频率  | 用途     |

### 5.4 多 Agent 协作流程

> 参考知识库 [05\_多Agent协作模式.md](../07_AI%20Agent产品设计/05_多Agent协作模式.md)
> 调研启示：引入 SOP 流程模板约束推理路径，防止 Agent 自由发挥导致幻觉。

```
告警 → [协调 Agent 路由] → [归因 Agent 提取故障信息]
  → [评审 Agent 判断是否收敛]
    → 不收敛 → [深挖 Agent 多轮排查] → 回到评审
    → 收敛 → [修复 Agent 生成方案] → 人工确认 → 执行 → [复盘沉淀]
```

SOP 约束机制：用专家经验总结的流程模板约束 Agent 推理路径，每个步骤需产出证据链，评审 Agent 校验证据是否支撑结论。

## 6. 技术方案

### 6.1 模型选型

> 调研启示：金融/政务对私有化部署需求强烈，需预留开源权重模型方案（Qwen3 / DeepSeek-Coder V3）。

| 用途        | 推荐模型 | 备选（私有化） | 选型理由 |
| --------- | ---- | --- | ---- |
| 主推理       | DeepSeek-V3 / GPT-4o | Qwen3 / DeepSeek-Coder V3 | 推理能力强，私有化备选 |
| Embedding | bge-m3 | bge-large-zh | 多语言多粒度，中文优秀 |
| Rerank    | bge-reranker-large | bge-reranker-m3 | 中文 RAG Rerank 业界领先 |
| 本地降级      | Qwen3-7B | DeepSeek-Coder V3 | 资源受限/气隙环境降级 |
| 时序建模 | Temporal Fusion Transformers | LSTM | 多尺度注意力，优于 LSTM |

### 6.2 Prompt 设计

> 参考知识库设计原则，此处放核心 Prompt 模板。调研启示：CCF 2025 冠军方案引入 SOP 约束提示，Privofine 将运维 QA 分四类微调。

**归因 Agent System Prompt（示例，含 SOP 约束）**：

```
你是一名资深 SRE，擅长运维故障归因。严格遵循以下 SOP 流程：
1. 解析告警：提取告警源、对象、指标、阈值、时间
2. 证据收集：调用工具检索关联日志/指标/变更/拓扑
3. 因果推断：区分"相关性"与"因果性"，拒绝把相关当因果
4. 输出根因候选列表，每个候选包含：
   - 根因描述
   - 置信度（高/中/低）
   - 支持证据（必须引用具体数据）
   - 建议的下一步排查动作
若证据不足，明确说明需要补充什么信息，不要臆测。
```

## 8. 权限与安全

> 参考知识库 [06\_产品权限设计详解.md](../03_AI产品设计/06_产品权限设计详解.md)

### 8.1 权限模型

| 维度   | 方案                        |
| ---- | ------------------------- |
| 功能权限 | RBAC（运维 / 主管 / 管理员）       |
| 数据权限 | 按业务线 / 环境隔离（生产 / 预发 / 测试） |
| 操作权限 | 高危操作（修复执行）需二次审批           |

### 8.2 安全要求

> 调研启示：气隙环境研究证明"日志转换 + 优先级排序"可减少 43% Token 消耗，对成本与安全双有益。

| 项           | 要求                     |
| ----------- | ---------------------- |
| 数据脱敏        | 日志中的密钥/PII 需脱敏后送 LLM   |
| Prompt 注入防护 | 用户输入与系统 Prompt 隔离      |
| 操作审计        | 全部 Agent 操作留痕，可追溯      |
| 人机协同        | 高危操作 Human-in-the-loop |
| 日志优先级排序 | 送 LLM 前做日志过滤+事件聚合+优先级排序，降低 Token 与泄露风险 |
| 合规          | TBD（等保 / 数据出境）         |

## 11. 风险与依赖

### 11.1 风险

> 调研启示：LLM 幻觉、私有化压力、成本失控、评估失真为四大典型风险。

| 风险          | 影响     | 概率     | 应对                     |
| ----------- | ------ | ------ | ---------------------- |
| LLM 幻觉导致误归因 | 高      | 中      | 证据链强制 + 推理过程评估（Reason 维度）|
| 高危操作误执行     | 极高     | 低      | Human-in-the-loop + 审批 |
| 数据权限泄露      | 高      | 中      | RAG 检索叠加权限过滤           |
| 模型成本超预算     | 中      | 中      | 配额限制 + 日志优先级排序（减 43% Token）+ 路由降级模型 |
| 评估失真（关键词匹配蒙对答案）| 高 | 中 | 过程导向评估，不只看最终答案 |
| 私有化部署压力 | 中 | 高 | 预留 Qwen3/DeepSeek-Coder V3 本地化方案 |
