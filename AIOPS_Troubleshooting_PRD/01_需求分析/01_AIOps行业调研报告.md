## 一、AIOps 行业现状

### 1.1 从 AIOps 1.0 到 2.0 的范式迁移

AIOps 自 2016 年被 Gartner 正式提出后，经历了近十年的演进，目前正处于从 **1.0（算法辅助）** 向 **2.0（自主智能）** 的关键转折点。

| 阶段 | 时代特征 | 核心能力 | 主要痛点 |
|------|----------|----------|----------|
| **AIOps 1.0** | 统计学习/机器学习/深度学习 | 异常检测、告警聚类、根因推测 | 黑盒决策不可解释、泛化能力弱、需大量标注 |
| **AIOps 2.0** | LLM + AI Agent | 自然语言理解、推理链路、可执行动作 | 幻觉风险、成本高、安全边界 |

Gartner 将 AIOps 演进分为五阶段：被动监控 → 主动监控 → 基础自动化 → 传统 AIOps → **智能自治**。大模型的引入主要集中在第四到第五阶段的跨越上，补上了从"识别异常"到"处置决策"中间的**理解与决策**空白。

### 1.2 2026 年三大趋势关键词

根据 2026 年 7 月 AIOps 技术进展月报，当前行业趋势可总结为三个关键词：

**① Agent 化**（最显著趋势）
- 运维场景从"问答式"大模型交互，向"自主感知 → 分析 → 决策 → 执行"的 Agent 模式演进
- 多款运维 Agent 产品发布或公测：阿里云 AIOps Agent、PagerDuty GenAI Copilot、LangChain 生产运维场景适配

**② 多模态**
- 从纯文本告警分析扩展到 **日志 + 指标 + Trace + 拓扑图** 的多模态融合理解
- Google Cloud Operations Suite 发布 "Multi-Modal Incident Analyzer"

**③ 私有化**
- 金融和政务行业对私有化部署呼声强烈
- 开源权重模型（**Qwen 3、DeepSeek-Coder V3**）在运维领域的微调方案密集发布

### 1.3 主流产品动态

| 产品 | 厂商 | 核心能力 | 状态 |
|------|------|----------|------|
| AIOps Agent | 阿里云 | 告警→根因→处置端到端自动化，含告警聚合引擎、根因定位引擎、预案执行引擎 | 公测 |
| GenAI Copilot | PagerDuty | 事件智能问答与处置建议 | 增强 |
| Multi-Modal Incident Analyzer | Google Cloud | 多模态事件分析 | GA |
| 大模型驱动 AIOps 平台 | 多家厂商 | 数据接入→告警治理→事件聚合→根因定位→自动处置→复盘报告 | 落地中 |

阿里云 AIOps Agent 的核心决策流程采用"告警聚合 → 根因定位 → 置信度判断 → 自动执行/人工介入"的闭环，**置信度阈值 0.75** 是自动执行与人工推荐的分界线。

## 二、LLM 在 AIOps 领域的应用

### 2.1 权威综述：LLM4AIOps

北京大学 Ying Li 教授团队于 **2025 年 9 月** 在 ACM Computing Surveys（CCF A 类期刊）发表了题为《A Survey of AIOps in the Era of Large Language Models》的综述，这是目前该领域最系统的研究梳理。

| 维度 | 核心发现 |
|------|----------|
| **样本规模** | 分析了 2020.01 - 2024.12 期间的 **183 篇研究论文** |
| **数据源** | 传统数据（指标/日志/Trace）+ LLM 启用的新数据源（事件报告/代码/文档） |
| **任务演进** | 出现新型任务，LLM 补齐了"理解 → 推理 → 表达"的能力空白 |
| **方法分类** | 单 Agent 工具增强 + 多 Agent 协作两大范式 |
| **评估方法** | 从"结果导向"向"过程导向"演进（推理链评估） |

### 2.2 LLM 在辅助修复的五个自动化层级

综述将辅助修复（Assisted Remediation）按自动化程度分为五层，这是 LLM 带来的根本性变化：

| 层级 | 名称 | 传统 AIOps | LLM 时代 |
|------|------|------------|----------|
| L1 | 辅助提问（Assisted Questioning） | ✓ | ✓ |
| L2 | 缓解方案生成（Mitigation Solution Generation） | ✓ | ✓ |
| L3 | 命令推荐（Command Recommendation） | ✗ | ✓ 新增 |
| L4 | 脚本生成（Script Generation） | ✗ | ✓ 新增 |
| L5 | 自动执行（Automatic Execution） | ✗ | ✓ 新增 |

**关键洞察**：传统 AIOps 的辅助修复只能停留在"方案生成"层级，LLM 的引入使"命令推荐 → 脚本生成 → 自动执行"三个高层级成为可能，这是 AIOps 2.0 自治能力的根基。

### 2.3 运维的"三类语义任务"与 LLM 能力拼图

行业实践表明，运维工程师的工作可归为三类语义任务，恰好对应 LLM 的核心能力：

| 任务类型 | 说明 | LLM 对应能力 |
|----------|------|--------------|
| **读** | 读告警/日志/工单/变更/监控 | 语义理解（字面各异但语义重叠的告警归一） |
| **推理** | 串联信息成因果链 | 拓扑+时序+业务上下文综合推理 |
| **表达** | 写复盘报告、生成处置脚本 | 自然语言生成（对 SRE 与 CTO 输出不同风格） |

LLM 不擅长的部分（精确数值计算、低延迟实时响应、严格事务一致性）恰由传统运维组件承担，两者是**互补关系而非替代关系**。

### 2.4 关键技术栈

| 技术组件 | 代表方案 | 作用 |
|----------|----------|------|
| 时序建模 | Temporal Fusion Transformers（优于 LSTM） | 多尺度注意力捕捉长期趋势+短期波动 |
| 因果推断 | 贝叶斯网络 + EM 算法 | 拒绝把"相关性"当"因果性" |
| 图神经网络 | GraphSAGE | 捕捉组件间接依赖，聚焦故障传播关键路径 |
| 知识图谱 | IT 组件依赖图谱 | 关联分析、根因定界 |
| RAG | 向量检索 + BM25 混合检索 | 运维知识问答、SOP 检索 |
| 多 Agent 协作 | MainAgent + ObAgent + JudgeAgent | 全局控制 + 故障提取 + 根因判断 |

### 2.5 AgentOps 新范式

LLM-based Agent 正在将微服务运维重塑为 **AgentOps** 范式，核心特征：

- **ReAct 风格工具调用**：Agent 主动调用日志查询、指标拉取、变更检索等工具
- **多 Agent 协作**：单 Agent 工具增强 → 多 Agent 协同诊断
- **推理过程可评估**：从"最终答案匹配"转向"推理链证据评估"

### 2.6 边缘与隔离环境的 LLM AIOps

首尔科技大学 2026 年 4 月在 EuroMLSys '26 发表的研究针对**气隙隔离环境**（air-gapped）的 LLM AIOps：

| 阶段 | 效果 |
|------|------|
| 日志转换（规则过滤+模式匹配） | 日志量减少 **76%** |
| 事件聚合（时间窗口归并） | 2445 万行 → 588 万行 → 20.7 万结构化事件 |
| 日志优先级排序 | 事件再减 **51%** |
| LLM Token 消耗 | 较未优先级方案减少 **43%** |

该研究证明，在资源受限的边缘场景，**日志转换 + 优先级排序**是让 LLM AIOps 落地的关键工程手段。

## 三、CCF 在 AIOps 及 LLM 的最新成果

### 3.1 CCF 国际 AIOps 挑战赛（行业最具影响力赛事）

**赛事概况**：由清华大学联合 CCF 自 2018 年发起，旨在借助社区力量用 AI 算法解决运维难题，迄今已举办八届，累计 **1900+ 参赛队伍、5000+ 选手、15 万+ 在线参与人数**，是智能运维领域最具影响力的专业赛事。

### 3.2 历届赛题演进（清晰反映技术演进路径）

| 届次 | 年份 | 赛题 | 参赛队数 | 技术特征 |
|------|------|------|----------|----------|
| 第1届 | 2018 | KPI 异常检测 | 125 | 统计学习/机器学习 |
| 第2届 | 2019 | 多维监测指标的异常定位 | 141 | 多维数据 |
| 第3届 | 2020 | 微服务故障发现和根因定位 | 141 | 引入调用链 |
| 第4届 | 2021 | 云环境下商业银行系统故障检测与根因定位 | 248 | 在线评测+建行云 |
| 第5届 | 2022 | 微服务电商系统故障识别与分类 | 300+ | 故障分类新方向 |
| 第6届 | 2023 | 开放式赛题 + **大语言模型在运维领域的应用** | 265+ | **首次引入 LLM** |
| 第7届 | 2024 | **基于检索增强的运维知识问答**（RAG + 5G 运维文档） | 649 / 533 | **RAG 范式确立** |
| 第8届 | 2025 | 双赛道：①大模型智能体微服务根因定位 ②无线网络因果预测 | 376 / 185 | **Agent 范式确立** |

**演进规律**：异常检测 → 根因定位 → 故障分类 → **LLM 应用** → **RAG 问答** → **Agent 根因定位**。技术路径与学术界的 LLM4AIOps 综述完全吻合。

### 3.3 2025 年第八届赛事亮点

| 赛道 | 主题 | 队伍数 | 奖金 | 核心创新 |
|------|------|--------|------|----------|
| 赛道一 | 基于大模型智能体的微服务根因定位 | 376 | ¥140,000 | **多智能体协作 + SOP 流程约束** |
| 赛道二 | 基于时间序列的无线网络因果预测与变更决策 | 185 | ¥140,000 | 多任务学习 + 因果预测 |

**赛道一的关键技术特征**：
- 引入 **"标准操作流程 SOP" 机制**，用专家经验总结的流程模板约束模型推理路径
- **多智能体协作框架**：MainAgent 全局控制 + ObAgent 自动提取故障信息 + JudgeAgent 判断是否找到根因
- 开源方案代表：MicroRCA-Agent（第五名，已开源），采用 Log/Trace/Metric 三模态分层 LLM 分析 + 多模态根因融合

### 3.4 2026 年第九届（进行中）

| 赛题 | 队伍数 | 截止 | 奖金 |
|------|--------|------|------|
| 基于多源观测数据的骨干网全栈故障诊断 | 30 | 2026-11-22 | ¥140,000 |
| 基于大模型智能体的微服务根因定位（延期版） | 32 | 2026-09-04 | ¥0 |

**新趋势**：从微服务场景扩展到**骨干网全栈故障诊断**，融合结构化观测数据，应对"网络拓扑复杂、故障类型多样、异常表征差异显著"三大挑战。

### 3.5 评测基准成果：AIOps2025 + RCA100

2026 年 6 月，中科院计算机网络信息中心、南开大学、阿里云、清华大学的联合团队发布了 **AIOps2025 + RCA100 多数据集基准**，这是 CCF AIOps 领域的重要学术贡献。

| 维度 | 内容 |
|------|------|
| **规模** | 500+ 专家标注故障案例 |
| **覆盖系统** | HipsterShop + OpenTelemetry Demo Store |
| **故障类型** | 资源、网络、运行时、中间件/数据库、应用逻辑 5 大类 |
| **评估范式** | 三维推理过程评估 |
| **验证规模** | 6000+ 参赛队伍验证 |

**三维评估框架**（突破传统"只看最终答案"的局限）：

| 维度 | 名称 | 评估问题 |
|------|------|----------|
| ① | Localization | 故障发生在哪？ |
| ② | Identification | 是什么类型的故障？ |
| ③ | Reason | 推理链是否有证据支撑？ |

该基准的核心贡献是**从结果导向转向过程导向**——防止 Agent 通过关键词匹配蒙对答案而实际推理链错误的问题。

### 3.7 Privofine：私域运维问答微调方法

上海第二工业大学与上海交通大学联合提出的 **Privofine** 方法（2026 年 4 月发表于《计算机科学与探索》），针对私域运维问答的微调难题：

| 维度 | 内容 |
|------|------|
| **问题分类** | 将运维 QA 划分为四类：设备安装、网络配置、性能优化、失效处理 |
| **数据增强** | 设计提示模板，自动生成多类型 QA 对 |
| **任务解耦** | 将问答样本解耦为三个子任务：判断任务、关联任务、回答任务 |
| **验证集** | 2024 CCF 国际 AIOps 挑战赛 5G 智能 O&M 数据集 |
| **效果** | 显著优于传统 LoRA 和领域特定微调方法 |

该方法对 AIOPS Troubleshooting 这类需要结合企业私域知识库的产品具有重要参考价值。

## 四、对 AIOPS Troubleshooting 项目的启示

### 4.1 技术选型建议

| 方向 | 调研依据 | 建议 |
|------|----------|------|
| Agent 架构 | CCF 2025 赛道一冠军方案采用多 Agent 协作 + SOP 约束 | 采用 MainAgent + ObAgent + JudgeAgent 三角色协作 |
| 根因分析 | 综述提出三维评估 + 多模态融合 | Log/Trace/Metric 分层 LLM 分析 + 多模态融合 |
| 知识库 | CCF 2024 赛题确立 RAG 范式 | RAG + 私域文档问答，参考 Privofine 微调方法 |
| 自动化层级 | 综述提出五层自动化 | 先做到 L3 命令推荐，L4/L5 慎重，高危操作必须 Human-in-the-loop |
| 评估基准 | AIOps2025 + RCA100 三维评估 | 引入 Localization + Identification + Reason 评估框架 |

### 4.2 风险预警

| 风险 | 调研依据 | 应对 |
|------|----------|------|
| LLM 幻觉导致误归因 | 综述明确指出 | 强制证据链 + 推理过程评估 |
| 私有化部署压力 | 金融/政务行业强烈需求 | 预留 Qwen3/DeepSeek-Coder V3 本地化方案 |
| 成本失控 | Token 消耗是 LLM AIOps 通病 | 借鉴日志优先级排序（减少 43% Token） |
| 评估失真 | 关键词匹配可蒙对答案 | 采用过程导向评估，不只看最终答案 |

| 资源 | 用途 |
|------|------|
| MicroRCA-Agent（GitHub） | 多模态根因分析参考实现 |
