## 一、什么是召回（Recall）

### 1.1 直观定义

**召回（Recall）**，也叫**查全率**，描述的是"在所有真正存在的正样本中，模型/系统成功找到了多少个"。

> 用一个生活化的比喻：
>
> 你在果园里摘苹果，果园里一共有 100 个红苹果（正样本），你摘到了 85 个红苹果，漏掉了 15 个，还误摘了 20 个青苹果（负样本）。
>
> 那么你的**召回率 = 85 / (85 + 15) = 85%**（100 个红苹果里找回了 85 个）
> 你的**精确率 = 85 / (85 + 20) ≈ 81%**（你摘下的 105 个苹果里有 85 个是对的）

召回率关心的是"不漏"，而不是"不误判"。

### 1.2 混淆矩阵基础

要理解召回率，必须先理解**混淆矩阵（Confusion Matrix）**。对于一个二分类任务，我们将样本划分为四类：

| | 预测为 正 | 预测为 负 |
|---|---|---|
| **实际为 正** | TP（真正例，找对了） | FN（假反例，漏掉了） |
| **实际为 负** | FP（假正例，误判了） | TN（真反例，正确排除） |

四个缩写的记忆口诀：

- **T**rue：预测与实际一致（对了）
- **F**alse：预测与实际不一致（错了）
- **P**ositive：预测结果是"正"
- **N**egative：预测结果是"负"

因此：

- **TP** = True + Positive → 预测正，实际正 → 对的
- **FP** = False + Positive → 预测正，实际负 → 错的（误报）
- **FN** = False + Negative → 预测负，实际正 → 错的（漏报）
- **TN** = True + Negative → 预测负，实际负 → 对的

### 1.3 召回率的数学公式

$$
\text{Recall} = \frac{TP}{TP + FN} = \frac{\text{正确找到的正样本数}}{\text{实际所有正样本数}}
$$

注意分母是 `TP + FN`，也就是**实际所有正样本的总数**，与模型预测结果无关。

召回率的取值范围是 [0, 1]，数值越大说明漏得越少：
- Recall = 1.0：完全没有漏网之鱼，所有正样本都被找到了
- Recall = 0.0：一个正样本都没找到，全漏了

### 1.4 一个完整的计算示例

某癌症筛查模型对 1000 人进行检测，结果如下：

- 实际患病（正样本）：100 人
- 实际未患病（负样本）：900 人
- 模型预测患病且实际患病（TP）：92 人
- 模型预测患病但实际未患病（FP）：45 人
- 模型预测未患病但实际患病（FN）：8 人
- 模型预测未患病且实际未患病（TN）：855 人

计算召回率：

```
Recall = TP / (TP + FN) = 92 / (92 + 8) = 92%
```

解读：所有真正患病的 100 人中，模型找出了 92 人，漏了 8 人。

同时计算其他指标做对比：

```
精确率 Precision = TP / (TP + FP) = 92 / (92 + 45) ≈ 67%
准确率 Accuracy  = (TP + TN) / 全部 = (92 + 855) / 1000 = 94.7%
```

可以看到，虽然准确率高达 94.7%，但精确率只有 67%（因为误判了 45 个健康人）。而召回率 92% 在医疗场景下是一个相对合格的指标。

## 二、召回率 vs 精确率 vs 准确率

这三个指标最容易混淆。下面用一张表彻底理清：

| 指标 | 回答的问题 | 公式 | 关注什么 | 场景偏好 |
|---|---|---|---|---|
| **召回率 Recall** | 所有真正的正样本里，找到了多少？ | TP / (TP+FN) | 不漏 | 医疗、风控、RAG 检索 |
| **精确率 Precision** | 我找到的这些正样本里，有多少是真的？ | TP / (TP+FP) | 不误判 | 垃圾邮件、广告推荐 |
| **准确率 Accuracy** | 所有预测中，有多少是对的？ | (TP+TN) / 全部 | 整体正确 | 类别均衡的分类任务 |

### 2.1 为什么"准确率"常常骗人

准确率是最"直觉"的指标，但在**样本不均衡**的场景下会严重失真。

极端例子：一个风控场景，每 1 万笔交易中只有 1 笔是欺诈（正样本率 0.01%）。如果模型永远预测"不是欺诈"（全部判负）：

```
TP = 0, FN = 1, FP = 0, TN = 9999
Accuracy = (0 + 9999) / 10000 = 99.99%
Recall   = 0 / (0 + 1) = 0%
```

准确率高达 99.99%，但召回率为 0% — 这个模型对风控业务毫无价值。这就是为什么在样本不均衡场景（医疗、风控、异常检测）**绝不能只用准确率**，必须看召回率。

### 2.2 Recall-Precision Trade-off

召回率和精确率通常是"跷跷板"关系：

- 如果你想**提高召回率**（少漏），就放宽判定阈值。比如癌症筛查，只要有一丝可疑就标记为"需要复查"。结果是漏掉的少了，但误判的（FP）也多了 → 精确率下降。
- 如果你想**提高精确率**（少误判），就收紧判定阈值。比如垃圾邮件，只有非常确信是垃圾才拦截。结果是误判少了，但漏掉的（FN）也多了 → 召回率下降。

这个权衡可以通过 **PR 曲线（Precision-Recall Curve）** 可视化。曲线下的面积叫 **AP（Average Precision）**，面积越大说明模型在各种阈值下的综合表现越好。

## 三、召回率的多分类扩展

### 3.1 宏平均 Macro Recall

当任务有多个类别时，先对每个类别单独计算 Recall，再取算术平均：

```
Recall(A) = TP_A / (TP_A + FN_A)
Recall(B) = TP_B / (TP_B + FN_B)
Recall(C) = TP_C / (TP_C + FN_C)

Macro-Recall = (Recall(A) + Recall(B) + Recall(C)) / 3
```

每个类别的权重相等，小样本类别对结果的影响与大类别相同。适用于"每个类别都很重要"的场景。

### 3.2 加权平均 Weighted Recall

按每个类别的样本数占比做加权平均：

```
Weighted-Recall = w_A·R_A + w_B·R_B + w_C·R_C
其中 w_A = (TP_A+FN_A) / 全部样本
```

大样本类别权重更高，适用于"整体业务价值由主要类别贡献"的场景。

### 3.3 微平均 Micro Recall

把所有类别的 TP 和 FN 加总后按二分类公式计算：

```
Micro-Recall = (TP_A + TP_B + TP_C) / (TP_A+TP_B+TP_C + FN_A+FN_B+FN_C)
```

在多分类且每个样本只属于一个类的场景下，Micro-Recall 等于 Micro-Precision 也等于准确率。

## 四、不同业务场景的召回率目标与取舍

| 场景 | 更看重 | 原因 | 典型召回率目标 |
|---|---|---|---|
| **癌症筛查 / 疾病早筛** | 召回率 | 漏诊可能致死，误诊只是多做一次检查 | ≥95% |
| **金融反欺诈 / 风控** | 召回率 | 漏一笔欺诈损失远大于误判一笔的人工审核成本 | ≥90%（视金额而定） |
| **内容安全 / 违规检测** | 召回率 | 漏一条违规可能导致平台被监管处罚 | ≥98% |
| **RAG 文档检索（召回阶段）** | 召回率 | 相关文档没进上下文，LLM 就无从回答 | ≥85%（top_k 场景） |
| **搜索引擎召回层** | 召回率 | 先保证相关文档都进入候选集，后续排序再筛选 | 越高越好 |
| **推荐系统召回层** | 召回率 | 先把用户可能感兴趣的内容都捞出来，排序模型再精排 | 根据体量 |
| **垃圾邮件过滤** | 精确率 | 把正常邮件判为垃圾邮件代价极高 | 不追求高召回，保证精确率 |
| **招聘简历初筛** | 精确率 | 给不合格候选人面试机会成本高 | 精确率优先 |
| **广告投放人群定向** | 精确率 | 曝光给非目标人群是浪费预算 | 精确率优先 |

### 4.1 决策框架：什么时候该优化召回率？

用下面三个问题快速判断：

1. **漏掉一个正样本的代价是否显著大于误判一个负样本的代价？** → 是，优化召回率
2. **后续是否还有"精筛"环节（如排序模型、人工审核、RAG 的 LLM 精读）？** → 是，召回阶段可以优化召回率
3. **正负样本比例是否极度不均衡？** → 是，准确率不可信，召回率更重要

## 五、召回率在 AI 产品中的应用

### 5.1 推荐系统中的召回

推荐系统通常分为 **召回 → 粗排 → 精排 → 重排** 四个阶段。

- **召回阶段**：从百万级候选池中捞出几百到几千个"用户可能感兴趣"的内容。核心指标就是召回率。
- **粗排 / 精排**：对召回结果做精准打分，看的是 AUC、CTR 预估准确率。

典型召回方式：
- 协同过滤召回
- 向量召回（用户向量 × 内容向量）
- 规则召回（热门、地域、人群标签）
- 多路召回：每种方式召回一部分，合并去重后送入排序

**PM 判断**：当用户抱怨"刷来刷去就是那些内容，没新意"，要检查多路召回的覆盖率和新颖性；当用户抱怨"推的东西完全不对"，要检查精排模型；当用户说"我明明喜欢 A 为什么从来不推"，优先排查召回率。

### 5.2 搜索系统中的召回

搜索引擎也分召回和排序。召回阶段决定了**候选文档池**，排序决定展示顺序。

- **高召回率 = 用户搜的关键词能命中相关文档**
- **低召回率 = 文档明明存在但用户搜不到**（典型痛点）

评估方法：人工标注一批 Query → 找到每个 Query 应该被命中的所有文档（golden set）→ 计算召回比例。

### 5.3 RAG 系统中的召回率（重点）

**RAG = Retrieval（检索） + Augmented（增强） + Generation（生成）**，检索阶段的召回率直接决定了 LLM 能否拿到足够的上下文信息来回答问题。

如果用户问的问题对应知识库中有 5 篇相关文档，但检索只召回了 2 篇：

```
RAG 召回率 = 2 / 5 = 40%
```

这意味着 LLM 在生成答案时缺少 3 篇文档的关键信息，答非所问、回答不完整的概率会很高。

**RAG 中提升召回率的工程手段**：

| 手段 | 说明 | 效果 |
|---|---|---|
| **增大 top_k** | 从默认 3 提升到 10~20 | 最直接，首选用 |
| **混合检索 Hybrid Search** | 向量检索 + BM25 关键词检索，合并结果 | 关键词精确匹配时效果显著 |
| **优化 Chunking** | 调整分块大小 / 增加 overlap（通常 10%~20%）| 避免信息被切分在两个块中 |
| **父文档召回** | 召回小块，返回父块（LangChain ParentDocumentRetriever）| 兼顾匹配精度与上下文完整性 |
| **多路召回** | 多个 embedding 模型 / 多种检索方式，结果去重合并 | 互补各自不足 |
| **Rerank 重排** | 召回扩大 top_k（如 50），通过 Cross-Encoder Rerank 选前 5 | 大幅提升有效召回 |
| **Query 改写** | 用 LLM 先把用户问题改写为更规范的检索式 | 消除口语化、指代不明 |
| **使用更好的 Embedding 模型** | 如 BGE-M3、Cohere-Embed | 向量语义匹配能力更强 |

## 六、如何衡量召回率：评估方法

### 6.1 标准流程

1. **准备测试集**：人工标注一批数据，明确哪些是"应该被召回的正样本"（golden set）。
2. **执行系统/模型**：拿到系统召回的结果集（predicted set）。
3. **计算 Recall**：`Recall = |predicted ∩ golden| / |golden|`。
4. **计算 Precision**：`Precision = |predicted ∩ golden| / |predicted|`。
5. **计算 F1**：`F1 = 2·P·R / (P+R)`，综合指标。

### 6.2 常见误区与陷阱

#### ❌ 误区1：只看召回率，不看精确率
召回率 = 100% 很容易做到，只要把所有候选都返回即可。但此时精确率极低，对业务价值为零（甚至为负，因为排序模型要处理巨量噪声）。**召回率必须与精确率/成本一起看。**

#### ❌ 误区2：评估集有选择偏倚
"我抽样了 1000 条系统召回的结果，人工标注发现召回率 95%" → 这是错的，因为你没统计那些系统没召回但应该被召回的样本。**正确做法：先定义完整的 golden set，再跑召回。**

#### ❌ 误区3：把 Hit Rate 当 Recall
"用户点了推荐的第 1 条就算命中" → 这是 Hit Rate，不是 Recall。Recall 是"所有该命中的都被召回了吗"，而不是"用户有没有点第一条"。

#### ❌ 误区4：评估集太小导致波动
评估集正样本只有 20 个，漏 2 个召回率就从 100% 掉到 90%，波动大不可信。**经验：每个关键类别至少有 200 个正样本，Recall 指标才相对稳定。**

#### ❌ 误区5：阈值固定不看业务
"召回率 80% 就达标了" — 达标线必须与业务对齐。癌症筛查 90% 召回率太低；垃圾邮件过滤 50% 召回率也可能够。

## 七、F1 值：召回率与精确率的调和平均

当需要一个综合指标来平衡召回和精确率时，使用 **F1 值**：

$$
F_1 = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}
$$

F1 是调和平均，意味着**较小的那个值会主导 F1**。P=80%, R=20% → F1 ≈ 32%，而不是算术平均的 50%。

如果业务更看重召回率（如医疗），可以用加权 Fβ：

$$
F_\beta = (1+\beta^2) \cdot \frac{P \cdot R}{\beta^2 P + R}
$$

- β = 1：标准 F1，权重相等
- β = 2：F2，召回率权重为精确率的 4 倍（医疗、风控）
- β = 0.5：F0.5，精确率权重更高（垃圾邮件）

## 八、实战案例

### 案例1：RAG 文档问答召回率优化

**背景**：AI PM 知识库 100+ 文档，准备 50 个用户常见问题作为评估集，每个问题人工标注"需要哪些文档/段落才能回答"。

**基线**：Chroma 向量检索 + top_k=3 + BAAI/bge-small-zh，召回率 52%，命中率（top_k 中有任意一个相关即算命中）68%。

**优化过程**：

| 步骤 | 改动 | Recall@10 | Recall@3 | 耗时 / 成本 |
|---|---|---|---|---|
| 0 | 基线（向量 + top_k=3） | - | 52% | 基准 |
| 1 | top_k 3 → 10 | 68% | 52% | 几乎无成本 |
| 2 | + BM25 混合检索，RRF 融合 | 81% | 59% | 建倒排索引，轻度耗时 |
| 3 | + BGE-Reranker 取前 3 | - | 74% | 增加 rerank 推理耗时 |
| 4 | + Query 改写（LLM） | - | 80% | 每次检索多一次 LLM 调用 |
| 5 | Chunk 从 500 调整为 300 + overlap 15% | - | 83% | 重新切块和向量化（一次性） |

**结果**：召回率从 52% → 83%，用户"答非所问"反馈率从 38% 下降到 9%。

### 案例2：电商风控拦截召回率

**背景**：某电商平台每日 500 万笔订单，其中 0.03% 为欺诈（约 1500 笔/天），模型初版召回率 70%，每天漏 450 笔，平均每笔损失 200 元 → 日损失 9 万元。

**优化方向**：

1. **多路召回**：规则引擎 + GBDT + GraphSAGE，三路并行召回，去重后召回率提升至 88%。
2. **分级阈值**：低欺诈风险走自动放行，中风险走二次模型判定，高风险直接拦截。通过放宽部分风险阈值，召回率进一步提升至 93%。
3. **人工审核兜底**：把模型拿不准的（score 模糊区间）送人工审核，每天 3000 单，多拦截 50 笔欺诈，召回率提升到 95%。

**结果**：召回率从 70% → 95%，日漏损从 9 万降至 1.5 万，加上审核人力成本后总体 ROI 为正。

## 九、PM 需要知道的工程常识

1. **召回率不是免费的**：提升 10% 召回率，可能意味着候选池扩大 3 倍，后续排序/推理成本显著增加，延迟变长。PM 要做的是业务收益 vs 成本的平衡点。

2. **召回 100% 不现实**：现实中追求的是"在预算 / 延迟可接受范围内的最高召回率"，而不是 100%。

3. **监控召回率的长期稳定性**：知识库变化、用户查询方式变化、模型老化都会导致召回率下降。需要设置回归测试集和自动告警。

4. **用户反馈是召回率的免费信号**：搜不到 → 收藏的东西推荐不出来 → 相关但没被展示 → 都是召回率问题。PM 可以通过埋点（如"无结果搜索词 Top 榜"）直接定位。

5. **召回指标不要孤立看**：召回率提升 20% 但业务指标（GMV、留存、点击率）没变化，说明召回的内容不相关或后续排序环节浪费了召回增益。

## 十、习题自测

1. 模型 A：Precision=99%，Recall=50%；模型 B：Precision=60%，Recall=95%。哪个适合做癌症筛查？哪个适合做垃圾邮件过滤？为什么？

2. 一批 10000 个产品缺陷检测，真正缺陷 200 个。模型检出 180 个缺陷，其中 150 个是真缺陷，30 个误报。计算 Recall、Precision、Accuracy、F1。

3. 你负责的 RAG 产品，用户反馈"有些问题答得不全，我知道知识库中有但它没提到"。列出你会排查的 5 个方向，并说明优先级。

4. 解释为什么在样本不均衡的分类任务中，准确率是一个具有误导性的指标。
