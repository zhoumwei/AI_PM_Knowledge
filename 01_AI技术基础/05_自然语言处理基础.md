# 自然语言处理基础

## 一、什么是自然语言处理（NLP）

自然语言处理是人工智能的一个分支，旨在让计算机能够理解、处理和生成人类语言。

**核心目标**：实现人机之间的自然语言交互。

## 二、NLP主要任务

### 1. 文本分类（Text Classification）

**定义**：将文本归类到预定义的类别中

**类型**：
- 二分类：垃圾邮件检测、情感分析
- 多分类：新闻分类、主题识别
- 多标签分类：文本标注、关键词提取

**常用模型**：
- TF-IDF + 机器学习
- CNN/RNN
- BERT等预训练模型

**评估指标**：准确率、精确率、召回率、F1分数

**应用场景**：
- 内容审核（色情/暴力/政治敏感）
- 情感分析（用户评论分析）
- 意图识别（客服对话）

---

### 2. 命名实体识别（NER）

**定义**：识别文本中的命名实体（人名、地名、组织机构名等）

**实体类型**：
- PER：人名（如"张三"）
- LOC：地名（如"北京"）
- ORG：组织机构名（如"百度"）
- DATE：日期（如"2023年10月"）
- MONEY：金额（如"100元"）

**常用模型**：
- CRF（条件随机场）
- BERT + CRF
- spaCy（工业级NLP库）

**应用场景**：
- 信息抽取（从新闻中提取关键信息）
- 知识图谱构建
- 智能问答（理解用户问题中的实体）

---

### 3. 文本摘要（Text Summarization）

**定义**：将长文本压缩为短文本，保留核心信息

**类型**：
- **抽取式摘要**：从原文中抽取关键句子
- **生成式摘要**：重新组织语言生成摘要

**常用模型**：
- TextRank（抽取式）
- BERT（抽取式）
- T5、BART（生成式）

**应用场景**：
- 新闻摘要
- 文档总结
- 会议记录整理

---

### 4. 机器翻译（Machine Translation）

**定义**：将一种语言翻译成另一种语言

**发展历程**：
- 规则翻译 → 统计翻译 → 神经机器翻译

**常用模型**：
- Transformer（Google Translate）
- BERT + Transformer
- mT5（多语言翻译）

**应用场景**：
- 实时翻译（Google翻译、有道翻译）
- 文档翻译
- 跨语言搜索

---

### 5. 问答系统（Question Answering）

**定义**：根据给定的上下文回答问题

**类型**：
- **抽取式问答**：从上下文中抽取答案
- **生成式问答**：生成新的答案
- **开放域问答**：不依赖特定上下文

**常用模型**：
- BERT（抽取式）
- GPT（生成式）
- RAG（检索增强生成）

**应用场景**：
- 智能客服（FAQ问答）
- 知识问答（百科知识）
- 阅读理解

---

### 6. 对话系统（Dialogue System）

**定义**：实现人机之间的多轮对话

**类型**：
- **任务型对话**：完成特定任务（如订机票）
- **闲聊型对话**：无特定目的的对话（如聊天机器人）
- **知识型对话**：基于知识的问答

**常用模型**：
- Seq2Seq（传统对话）
- GPT系列（生成式对话）
- Rasa（开源对话框架）

**核心挑战**：
- 上下文理解
- 意图识别
- 回复生成的连贯性

---

### 7. 文本生成（Text Generation）

**定义**：根据输入生成新的文本

**技术方法**：
- RNN/LSTM
- Transformer（GPT系列）
- 扩散模型

**应用场景**：
- 内容创作（文章、故事）
- 代码生成（GitHub Copilot）
- 诗歌生成

---

## 三、文本预处理

### 1. 文本表示

**方法**：
- **词袋模型（Bag of Words）**：忽略词序，统计词频
- **TF-IDF**：考虑词的重要性
- **Word Embedding**：将词映射到向量空间
- **BERT Embedding**：上下文相关的词向量

### 2. 预处理步骤

```
原始文本 → 分词 → 去停用词 → 词干化/词形还原 → 向量化
```

### 3. 分词（Tokenization）

**中文分词**：
- jieba（结巴分词）
- HanLP
- THULAC

**英文分词**：
- spaCy
- NLTK

### 4. 停用词（Stop Words）

**定义**：高频但无意义的词（如"的"、"是"、"and"）

**处理方法**：过滤停用词，减少噪声

## 四、NLP产品架构

### 1. 典型架构

```
文本输入 → 预处理 → 模型推理 → 后处理 → 结果输出
```

### 2. 关键组件

| 组件 | 说明 |
|------|------|
| 文本采集 | 用户输入、爬虫、文档导入 |
| 预处理模块 | 分词、去停用词、向量化 |
| 模型推理 | 调用NLP模型 |
| 后处理 | 结果格式化、置信度过滤 |
| 反馈收集 | 用户纠错、标注数据收集 |

### 3. 性能优化

| 优化方向 | 方法 |
|----------|------|
| 模型压缩 | 量化、剪枝、蒸馏 |
| 推理加速 | ONNX、TensorRT |
| 缓存机制 | 缓存常见问题的答案 |

---

## 五、产品经理关注点

### 1. 数据需求

- **标注数据**：训练需要大量标注文本
- **领域数据**：行业特定术语和表达方式
- **数据质量**：标注准确性和一致性

### 2. 性能指标

| 指标 | 说明 |
|------|------|
| 准确率 | 预测正确的比例 |
| 推理延迟 | 响应时间 |
| 吞吐量 | 每秒处理请求数 |
| 用户满意度 | 人工评估结果质量 |

### 3. 部署考量

- **模型选择**：轻量级模型vs大型模型
- **部署方式**：云端API vs 本地部署
- **成本控制**：API调用成本、算力成本

### 4. 常见挑战

- **歧义处理**：一词多义
- **上下文理解**：长对话中的上下文依赖
- **领域适配**：通用模型在特定领域效果差
- **多语言支持**：跨语言处理
