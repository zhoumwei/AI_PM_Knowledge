# 模型评估

> 所属维度：AI 专项能力 ｜ 参考分：76

## 一、能力定义

模型评估是设计一套**可量化、可复现、可对比**的方法，衡量 AI/模型在具体业务场景下"好不好、能不能上线、改版有没有变好"。

> 无法度量就无法改进。模型评估是 AI 产品区别于传统软件的核心能力——传统软件测"功能对不对"，AI 还要测"效果好不好、稳定不稳定"。

## 二、评估的两大阶段

### 2.1 离线评估（Offline）
上线前，在固定标注数据集上批量评测：
- 优点：快、可复现、成本低、可反复回归
- 用途：模型选型、Prompt 迭代、版本对比、上线门槛

### 2.2 在线评估（Online）
上线后，在真实流量中评估：
- A/B 测试、灰度发布、真实用户反馈、业务指标
- 用途：验证离线结论、发现真实分布问题、度量业务价值

原则：**离线达标 → 小流量灰度 → 在线 A/B → 全量**。离线好不代表在线好。

## 三、评估数据集构建

| 要素 | 要求 |
|------|------|
| 代表性 | 覆盖真实分布（高频、长尾、边界、异常） |
| 标注质量 | 明确标注规范，多人标注算一致性（Kappa） |
| 黄金集 | 一批稳定、高质量的核心用例，用于回归 |
| 规模 | 分类/检索几百到几千条；生成类至少数十到数百 |
| 难例集 | 专门收集 bad case、对抗样本、边界情况 |
| 更新 | 随业务变化持续补充，防止"应试" |

## 四、不同任务的评估指标

### 4.1 分类/检索类（有标准答案）
| 指标 | 含义 |
|------|------|
| 准确率 Accuracy | 整体判对比例（类别均衡时用） |
| 精确率 Precision | 预测为正中真正为正的比例（"准不准"）|
| 召回率 Recall | 真正为正中被找出的比例（"全不全"）|
| F1 | Precision 与 Recall 的调和平均 |
| Top-K 准确率/召回率 | 正确答案出现在前 K 个结果中的比例 |
| MRR / NDCG | 排序质量（正确结果排得靠不靠前）|

### 4.2 生成类（开放文本，无唯一答案）
| 方法 | 说明 |
|------|------|
| 人工评分 | 按评分维度（准确性/相关性/流畅性/有害性）打分，最可靠但贵 |
| LLM-as-Judge | 用强模型当裁判批量打分，需校验与人工的一致性 |
| 忠实度/引用正确性 | 回答是否忠于检索材料、引用是否真实（RAG） |
| 拒答合理性 | 该拒的拒了、不该拒的没拒 |
| BLEU/ROUGE | 与参考文本的重合度（仅特定场景参考，易误导） |

### 4.3 Agent 类（过程 + 结果）
除了最终结果对不对，还要看过程：
- 任务完成率、步数/效率、工具调用正确率
- 是否误调危险工具、是否陷入无效循环

## 五、三维过程评估（CCF AIOps2025/RCA100 启示）

传统评估只看"最终答案对不对"，容易被"关键词匹配蒙对"骗过。过程导向的三维框架：

| 维度 | 评估问题 |
|------|----------|
| Localization（定位） | 问题/故障**发生在哪**？ |
| Identification（识别） | **是什么类型**的问题？ |
| Reason（推理） | 推理链是否**有证据支撑**、逻辑是否成立？ |

**产品启示**：评估 AI 排障/诊断类产品时，应要求 Agent 输出可核查的推理链，而非只比对最终标签。

## 六、评估方法与工具

| 方法 | 用途 |
|------|------|
| 混淆矩阵 / PR 曲线 | 分类效果分析、阈值选择 |
| 人工标注评审 | 生成类金标准 |
| LLM-as-Judge | 批量、低成本初评 |
| A/B 测试 | 在线效果验证（见 [A/B 测试模板](../../02_AI产品方法论/07_A-B测试可执行方案模板.md)） |
| 影子模式（Shadow） | 新模型只预测不执行，与现网对比 |
| 工具：Ragas / LangSmith / 自建评测平台 | RAG 与 LLM 应用评测 |

## 七、评估流程（工程化）

```
定义业务成功标准 → 建标注数据集 + 黄金集 → 定指标与门槛
  → 离线评测（选型/Prompt/版本对比）→ 人工抽检校准
  → 影子模式 → 小流量灰度（在线指标 + 人工标注）
  → A/B 测试 → 达标全量 → 持续监控 + bad case 回流
```

### 上线门槛示例
- 离线 Top-3 召回率 ≥ 85%
- 生成回答人工评分 ≥ 4/5，严重幻觉率 < 1%
- 在线灰度 4 周，核心业务指标不下降、无 P0 事故

## 八、效果-成本-延迟的联合评估

不能只看效果，要联合看：
- 同一指标下，模型 A vs B 的**单次成本**差异
- **延迟**（首 token、P95）是否达标
- 常用"每提升 1 个点准确率的边际成本"辅助决策
- 模型路由：用"效果/成本"矩阵决定哪些任务走旗舰模型、哪些走小模型

## 九、常见误区

| 误区 | 纠正 |
|------|------|
| 只看主观感觉"好像变好了" | 用固定数据集和量化指标 |
| 只评估最终答案 | Agent/诊断类要评估推理过程 |
| 用训练题做测试题 | 评测集严格隔离，防数据泄漏 |
| 评测集长期不更新 | 持续加入新 bad case |
| 离线好就直接全量 | 必须灰度+在线 A/B |
| LLM 裁判当绝对真理 | 定期用人工抽检校准裁判 |
| 只看准确率不看成本延迟 | 联合评估，综合决策 |
| 样本太少就下结论 | 关注样本量与统计显著性 |

## 十、实战案例（AIOPS 排障指标）

| 指标 | 目标 |
|------|------|
| 归因 Top-1 准确率（Localization） | 待基线确定 |
| 归因 Top-3 召回率 | ≥ 85% |
| 故障类型识别准确率（Identification） | 待基线 |
| 推理链证据支撑率（Reason） | ≥ 90% |
| 修复建议采纳率 | ≥ 40% |
| 完整归因 P95 延迟 | ≤ 30s |

## 十一、自测题

1. 你的黄金评测集有多少条？覆盖了哪些长尾和边界？
2. 生成类回答你用什么评估？LLM 裁判与人工评分的一致性如何？
3. 如何防止"关键词蒙对答案"导致的评估失真？
4. 模型 A 准确率高 2 个点但成本贵 3 倍，你怎么选？
5. 离线指标达标但线上效果差，可能有哪些原因？
