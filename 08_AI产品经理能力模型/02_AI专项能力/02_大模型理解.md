# 大模型理解

> 所属维度：AI 专项能力 ｜ 参考分：68

## 一、能力定义

理解大语言模型（LLM）的**基本原理、能力边界、性能特征、成本结构和选型逻辑**，从而能做出合理的产品决策，而不是把模型当"魔法黑盒"。

PM 不需要会训练模型，但必须能回答："这个需求模型能不能做、用哪个模型、大概多贵、可能出什么错"。

## 二、LLM 工作原理（够用即可的程度）

### 2.1 一句话理解
大模型本质是一个**超大规模的"下一个词预测器"**：基于海量文本训练，给定上文，概率性地预测最可能接续的内容。规模足够大后涌现出推理、总结、翻译、代码等能力。

### 2.2 关键概念

| 概念 | 含义 | 对产品的影响 |
|------|------|--------------|
| Token | 模型处理文本的最小单位（中文约 1 字≈1-2 token） | 计费与上下文长度单位 |
| 上下文窗口 | 单次能处理的最大 token 数（输入+输出） | 能塞多少资料/历史 |
| 温度（Temperature） | 值越高越随机有创意，越低越确定 | 事实任务调低，创作调高 |
| 幻觉（Hallucination） | 一本正经地编造不存在的内容 | 必须设计兜底与校验 |
| 参数量 | 模型规模（7B/70B/…） | 影响能力、成本、部署条件 |
| 预训练 / SFT / RLHF | 基座训练→指令微调→人类反馈对齐 | 理解模型能力来源 |
| 流式输出 | 逐 token 返回 | 影响交互体验 |

### 2.3 模型的三类部署形态
1. **闭源云端 API**：GPT、Claude、Gemini、通义、豆包——能力强、省心、数据出域、按量付费
2. **开源权重模型**：Qwen、DeepSeek、Llama——可私有化、数据安全、需自建推理
3. **自研/微调模型**：基于开源模型做领域 SFT/LoRA——成本高、数据门槛高、领域效果优

## 三、模型能力边界（重要预期管理）

**模型擅长**：理解与生成自然语言、总结归纳、翻译、写作、代码生成、基于给定材料推理、格式转换。

**模型不擅长 / 会犯错**：
- 精确数学计算与大量符号运算（需借助工具/代码）
- 实时信息（训练数据有截止日期，需联网/RAG）
- 私有/内部知识（需 RAG 或微调）
- 100% 的事实准确性（会幻觉）
- 严格的事务一致性、确定性结果
- 超长上下文中的信息检索（中间内容易被忽略）

**产品启示**：把不擅长的部分交给传统系统/工具（检索、计算、执行），LLM 负责理解、推理、表达——这正是 RAG 与 Agent 存在的原因。

## 四、主流模型速览（2026）

| 模型 | 提供方 | 特点 | 典型场景 |
|------|--------|------|----------|
| GPT-4o / o 系列 | OpenAI | 综合能力强、多模态、推理强 | 通用高端、复杂推理 |
| Claude | Anthropic | 长文本、写作、安全对齐好 | 长文档、代码 |
| Gemini | Google | 多模态、与 Google 生态 | 多模态 |
| DeepSeek-V3/R 系列 | 深度求索 | 开源/低成本、推理强、性价比高 | 私有化、成本敏感 |
| Qwen 系列 | 阿里 | 开源、尺寸齐全、中文好 | 国内私有化首选之一 |
| Llama | Meta | 开源生态成熟 | 海外/自建 |

> 模型能力快速迭代，应以最新榜单（LMSYS Chatbot Arena）和**自己业务数据集上的评测**为准，不能只看宣传。

## 五、成本模型（PM 必懂）

### 5.1 计费逻辑
主流 API 按 token 计费：**费用 =（输入 token × 输入单价 + 输出 token × 输出单价）**。输出单价通常显著高于输入（约 3-5 倍）。

### 5.2 影响单次成本的因素
- Prompt 长度（系统指令 + 检索内容 + 历史）
- 输出长度（让模型简短输出可省钱）
- 模型档位（旗舰 vs 轻量，价差可达数十倍）
- 调用次数（多轮、多 Agent 会倍增）

### 5.3 降本手段（详见商业化-成本控制）
模型路由（简单问题用小模型）、缓存复用、Prompt 压缩、上下文筛选、批处理、私有化小模型。

## 六、模型选型决策框架

| 维度 | 关键问题 |
|------|----------|
| 效果 | 在**我自己的业务数据集**上表现如何？（非只看榜单） |
| 语言/领域 | 中文？专业术语？是否需领域微调？ |
| 上下文 | 需要塞多长的资料？ |
| 成本 | 预估调用量下的月度账单？毛利率可接受？ |
| 延迟 | 首 token 与完整响应速度能否达标？ |
| 数据合规 | 数据能否出域/出境？是否必须私有化？ |
| 稳定性 | SLA、限流、厂商锁定风险？ |
| 多模态 | 是否需要图像/语音？ |

**实践建议**：主模型 + 备选模型（含私有化），通过统一抽象层接入，便于随时切换和 A/B。

## 七、常见误区

| 误区 | 纠正 |
|------|------|
| 模型越大约好 | 匹配场景，小模型常够用且便宜 |
| 只看通用榜单选型 | 必须在自己的评测集上测 |
| 认为模型知道公司内部信息 | 私有知识必须 RAG/微调 |
| 忽视输出 token 成本 | 输出往往是成本大头 |
| 把模型当确定性程序 | 输出有概率性，需校验与兜底 |
| 认为私有化一定更便宜 | 自建推理+运维成本常被低估 |

## 八、自测题

1. 同一个问题，旗舰模型答得好而某小模型答不好，可能有哪些原因？
2. 估算一个功能：日均 1 万次调用，每次输入 2000 token、输出 500 token，月成本大概多少（用你了解的单价）？
3. 什么情况下你会选择私有化开源模型而非云 API？
4. 你的产品里，哪些任务应该"不让 LLM 做"而交给传统系统？
