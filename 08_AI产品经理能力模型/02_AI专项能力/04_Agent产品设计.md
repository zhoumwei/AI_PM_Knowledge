# Agent 产品设计

> 所属维度：AI 专项能力 ｜ 参考分：74

## 一、能力定义

AI Agent（智能体）是能**自主感知环境、进行推理决策、调用工具并执行动作**以完成目标的 AI 系统。Agent 产品设计能力，指 PM 能定义 Agent 的角色、任务边界、工具能力、决策流程、人机协同方式与安全机制。

如果说 RAG 是"会查资料的模型"，Agent 就是"会动手办事的助手"。

## 二、Agent 与 Chatbot 的区别

| 维度 | Chatbot（对话机器人） | Agent（智能体） |
|------|----------------------|-----------------|
| 交互 | 单轮/多轮问答 | 目标驱动，自主多步执行 |
| 工具 | 通常不调用 | 主动调用 API/工具/系统 |
| 决策 | 被动回答 | 自主规划下一步 |
| 状态 | 弱 | 有任务状态与记忆 |
| 典型 | 客服问答 | 自动排障、自动下单、研究助理 |

## 三、Agent 的核心能力构成

1. **感知**：接收用户指令、环境信息、事件（如告警）
2. **规划（Planning）**：拆解目标为步骤（ReAct、CoT、任务分解）
3. **记忆（Memory）**：短期（当前任务上下文）+ 长期（历史、知识库、用户偏好）
4. **工具使用（Tool Use / Function Calling）**：调用搜索、数据库、内部 API、代码执行
5. **决策与执行**：选择动作、执行、观察结果、再决策（循环）
6. **反馈与终止**：判断任务是否完成、何时请求人类帮助

## 四、核心机制：ReAct 循环

```
Thought（思考：现在该做什么）
   → Action（行动：调用某个工具）
   → Observation（观察：工具返回了什么）
   → Thought（再思考：基于结果下一步）
   → … 循环直到 Final Answer（给出最终结果）
```

这是 Agent"边想边做、根据反馈调整"的基本模式。

## 五、Function Calling（工具调用）

Agent 通过结构化方式调用外部能力：
- PM 需定义：有哪些工具、每个工具的用途、入参、出参、风险等级
- 示例工具：查询日志、拉取指标、检索变更、查询拓扑、执行重启、创建工单
- 关键设计：
  - 工具描述要清晰（模型靠描述判断何时调用）
  - 参数校验（防止模型传错参数）
  - 幂等性、超时、失败重试
  - **危险工具的权限与审批**

详见 [04_Function Calling技术.md](../../07_AI%20Agent产品设计/04_Function%20Calling技术.md)。

## 六、多 Agent 协作

复杂任务由多个专职 Agent 协作完成。CCF 2025 微服务根因定位的代表性分工：

| Agent | 职责 |
|-------|------|
| MainAgent（协调） | 全局控制、任务路由、编排 |
| ObAgent（观察） | 自动提取故障信息（日志/指标/链路） |
| JudgeAgent（评审） | 判断是否已找到根因、是否继续深挖 |

常见协作模式：流水线（pipeline）、专家分工、协商谈判、层级调度。PM 要设计：任务如何分配、Agent 间如何传递信息、冲突如何裁决、循环何时终止。

详见 [05_多Agent协作模式.md](../../07_AI%20Agent产品设计/05_多Agent协作模式.md)。

## 七、产品设计的关键决策（PM 重点）

### 7.1 自动化层级（L1-L5）
| 层级 | 能力 | 本期取舍 |
|------|------|----------|
| L1 | 辅助提问/信息聚合 | 通常先做 |
| L2 | 方案/缓解建议 | 通常先做 |
| L3 | 命令推荐 | 谨慎开放 |
| L4 | 脚本生成 | 需严格审核 |
| L5 | 自动执行 | 仅限低风险，高危人工确认 |

### 7.2 Human-in-the-loop（人在回路）
- 高危动作（重启、删除、变更、支付）必须人工确认
- 置信度阈值：高于阈值自动执行低风险操作，低于阈值转人工（行业参考：阿里云 AIOps 取 0.75）
- 可随时中断、接管、纠正 Agent

### 7.3 可解释与信任
- 过程可见：向用户展示"正在查日志…正在分析变更…"
- 结论带证据：每个根因/建议附数据依据
- 多候选 + 置信度，而非一个"黑盒结论"

### 7.4 SOP 约束
用专家流程模板约束 Agent 推理路径，防止自由发散与幻觉，同时让输出符合企业规范。

### 7.5 失败与兜底
- 工具调用失败：重试 / 换路径 / 上报
- 推理陷入循环：设最大步数强制退出
- 无法定位：明确说明并转人工，不硬编结论
- Agent 超时：降级为人工流程

### 7.6 成本控制
多步、多 Agent 会成倍放大 token 消耗——需做上下文筛选、模型路由、步数限制（详见[成本控制](../04_商业化能力/04_成本控制.md)）。

## 八、PM 设计流程

```
明确目标与成功标准 → 拆解任务步骤 → 定义工具清单（含风险等级）
  → 定义决策/终止/转人工条件 → 设计人机协同界面 → 定义评估指标
  → PoC 验证 → 灰度（先只建议不执行）→ 逐步放开自动化层级
```

## 九、常见误区

| 误区 | 纠正 |
|------|------|
| 把聊天框包装一下就叫 Agent | Agent 的核心是自主规划+工具执行 |
| 一上来就做全自动执行（L5） | 从 L1-L2 建议起步，逐步建立信任 |
| 工具给得越多越好 | 工具过多会导致选错；描述要精准 |
| 无步数/成本限制 | 可能陷入循环、账单失控 |
| 过程不可见 | 用户不信任、无法干预 |
| 不做权限与审批 | 高危误操作风险极高 |
| 用结果对不对单一评估 | 还要评估推理过程是否合理 |

## 十、实战案例（AIOPS 排障 Agent）

```
告警 → MainAgent 路由 → ObAgent 提取故障信息（查日志/指标/变更/拓扑）
  → JudgeAgent 评估是否收敛
    ├─ 未收敛 → 深挖 Agent 多轮排查 → 回到评审
    └─ 收敛 → 修复 Agent 生成方案（L3 命令推荐）
            → 高危操作人工确认 → 执行 → 复盘沉淀
```
本期边界：做到 L3（命令推荐），L4/L5 不做。详见 [00_PRD_主文档.md](../../AIOPS_Troubleshooting_PRD/00_PRD_主文档.md)。

## 十一、自测题

1. 你的 Agent 有哪些工具？请为每个标注风险等级和是否需要审批。
2. 哪些动作自动执行、哪些人工确认？判断依据是什么？
3. Agent 陷入循环或工具失败时，产品如何兜底？
4. 如何向用户展示 Agent 的"思考过程"以建立信任？
5. 多 Agent 之间信息如何传递、冲突如何裁决？
