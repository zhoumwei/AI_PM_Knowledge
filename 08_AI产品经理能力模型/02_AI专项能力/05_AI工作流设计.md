# AI 工作流设计

> 所属维度：AI 专项能力 ｜ 参考分：70

## 一、能力定义

AI 工作流设计是把**多个 AI 能力（理解、检索、推理、生成、审核）与传统系统节点编排成一条完整、可控、可观测的业务流程**。

单个 LLM 调用解决的是"点"，工作流解决的是"线"——把点连成稳定可靠的业务闭环。

## 二、为什么需要工作流

- 复杂业务无法靠"一次 Prompt"完成，需要多步骤、多模型、多工具配合
- 纯 Agent 自主决策不可控、成本高、易发散
- 工作流用**确定性的流程骨架**约束 AI 的不确定性，兼顾效果与可控性

> 实践趋势：**Workflow（固定编排）与 Agent（自主决策）结合**——主干流程固定，关键节点让 Agent 灵活决策。

## 三、工作流的基本节点类型

| 节点 | 作用 | 示例 |
|------|------|------|
| 输入/触发 | 启动流程 | 用户提交、告警事件、定时触发 |
| 预处理 | 清洗、分类、抽取 | 提取告警字段、意图识别 |
| 条件分支 | 按规则走不同路径 | 问题类型路由到不同处理 |
| AI 处理 | 调用模型 | 总结、归因、生成 |
| 检索 | RAG/数据库查询 | 查知识库、查日志 |
| 工具调用 | 执行动作 | 调 API、建工单 |
| 人工节点 | 人审/确认 | 高危操作审批 |
| 并行/汇聚 | 并发执行后合并 | 多路检索结果融合 |
| 后处理 | 格式化、质检 | 结构化校验、敏感词过滤 |
| 输出 | 交付结果 | 回复、报告、通知 |

## 四、核心编排模式

1. **顺序流水线（Pipeline）**：A→B→C，简单清晰，适合标准流程
2. **条件路由（Router）**：根据意图/类别分流到不同子流程
3. **并行处理 + 聚合**：多个任务并发（如多路检索、多模型投票）后合并
4. **迭代/循环**：处理结果不达标时回到某步重做（配合评审节点）
5. **人机协同**：AI 处理 → 人工审核/补充 → AI 继续
6. **Map-Reduce**：批量内容逐个处理后汇总（如长文档分段总结再合并）

## 五、设计要点

### 5.1 流程可控性
- 明确每个节点的输入输出契约（schema）
- 关键路径用确定规则，非关键环节交给模型
- 设置循环最大次数、整体超时、成本上限

### 5.2 异常与容错
- 每个节点定义失败处理：重试（几次）、降级、跳过、转人工
- 节点间数据校验（上游输出不符合下游预期时怎么办）
- 断点续跑（长流程中断后能恢复）

### 5.3 可观测性
- 记录每个节点的输入输出、耗时、模型版本、token
- 流程可视化（运行到哪一步、卡在哪）
- 便于定位是哪个节点出了问题

### 5.4 人工节点设计
- 什么条件触发人审（置信度低、高危、金额大）
- 人审界面：展示 AI 的结论与证据、提供批准/修改/驳回
- 人审结果如何回流（作为标注数据优化模型）

### 5.5 可复用与可配置
- 节点尽量做成可复用组件（如统一的"LLM 调用节点""审核节点"）
- 流程参数可配置（阈值、模型、分支规则），减少硬编码

## 六、典型工作流示例（智能排障）

```
[触发：告警]
   → [预处理：抽取字段/去重聚合]
   → [分支：是否已知故障模式？]
        ├─ 是 → [检索匹配历史 SOP] → [生成处置建议]
        └─ 否 → [多路并行：查日志/指标/变更/拓扑] → [聚合] → [LLM 归因]
   → [评审节点：置信度是否达标？]
        ├─ 否（<0.75）→ [转人工 / 深挖循环]
        └─ 是 → [生成修复命令 L3]
   → [人工确认节点] → [执行节点] → [生成复盘报告] → [沉淀知识库]
```

## 七、主流编排工具

| 工具 | 特点 | 适合 |
|------|------|------|
| LangGraph | 代码级、状态图、灵活可控 | 复杂 Agent 工作流 |
| Dify | 开源、可视化、知识库一体 | 快速搭建企业 AI 应用 |
| Coze（扣子） | 低代码、插件丰富、上手快 | 原型/Bot |
| n8n | 通用自动化、集成多 | 连接各类 SaaS |
| 自研引擎 | 完全可控 | 大型/高安全场景 |

PM 应能用 Dify/Coze 快速验证想法，能画清流程图与研发对齐 LangGraph 等工程实现。

## 八、与 Agent 的关系（如何选择）

| 选择 | 适用 |
|------|------|
| 固定 Workflow | 流程稳定、步骤可预知、强合规（如审批、标准排障 SOP） |
| 自主 Agent | 任务开放、路径无法预先穷举（如开放式研究） |
| 混合 | 主干 Workflow + 局部 Agent 决策（生产环境推荐） |

## 九、常见误区

| 误区 | 纠正 |
|------|------|
| 所有逻辑都让 Agent 自主决定 | 主干用固定流程保可控 |
| 节点输入输出不定义 schema | 节点间容易对不上 |
| 不设计节点失败处理 | 一处失败整条崩 |
| 无步数/成本上限 | 循环失控、成本爆炸 |
| 流程不可观测 | 出问题无法定位节点 |
| 过度编排（几十节点） | 复杂度高、维护难，先简后繁 |
