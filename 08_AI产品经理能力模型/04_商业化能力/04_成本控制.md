# 成本控制

> 所属维度：商业化能力 ｜ 参考分：54

## 一、能力定义

成本控制能力指在**保证 AI 效果与体验的前提下，系统性降低模型调用与基础设施成本**，使产品具备健康毛利。这是 AI 产品区别于传统软件最特有的商业化能力——传统软件边际成本趋近于零，而 AI 产品**用得越多、推理成本越高**。

## 二、AI 产品的成本构成

| 成本类型 | 内容 |
|----------|------|
| 模型推理成本（最大头） | 输入/输出 token 费用、调用次数 |
| 基础设施 | 服务器、GPU、向量库、带宽 |
| 检索/RAG | embedding 计算、向量库运行、Rerank |
| 数据成本 | 标注、清洗、微调数据集 |
| 微调/训练 | 训练算力（一次性但高） |
| 运维与人力 | 平台维护、私有化部署交付 |

**核心公式**：
```
单次请求成本 = (输入token × 输入单价 + 输出token × 输出单价) + 检索/工具成本 + 固定成本分摊
输出 token 单价通常是输入的 3-5 倍，是成本大头。
```

## 三、成本控制的六大手段

### 3.1 模型路由（Model Routing）——效果最显著
让"简单任务走小模型/便宜模型，复杂任务走旗舰模型"。
- 先用一个轻量模型或分类器判断任务难度/意图
- 简单问答（寒暄、格式转换、明确事实）→ 小模型
- 复杂推理、多步诊断 → 旗舰模型
- 可叠加"小模型先答，信心不足再升级"的级联策略
- 预期节省：30%-70%，需用评测集保证升级策略不伤效果

### 3.2 缓存（Caching）
- 相同/高度相似的请求直接复用结果（如重复问题、热点知识问答）
- embedding 结果可缓存（同一段文本不必重复向量化）
- 命中率越高越省，客服/高频问答场景节省 20%-60%
- 注意：缓存失效策略、个性化内容不适合强缓存

### 3.3 Prompt 与上下文优化
- 精简系统指令，去掉冗余示例
- **只送相关上下文**：RAG 少取、准取，不把大段无关日志/文档全塞进去
- 用更短的输出要求（"用 100 字以内回答"）直接砍输出 token
- 历史对话做摘要压缩，而非全量携带

### 3.4 数据预处理与优先级筛选
研究案例（气隙环境 LLM AIOps，EuroMLSys 2026）：
- 日志先经规则过滤+模式匹配，日志量减少约 76%
- 事件聚合 + 优先级排序，事件再减 51%
- 最终 LLM token 消耗减少约 **43%**

启示：**把噪声和无关数据在进入 LLM 之前过滤掉**，既省钱又降噪、还降低敏感信息暴露。

### 3.5 配额与限流
- 按套餐/用户设置调用与 token 配额
- 异常用量检测（防止滥用、脚本刷量、死循环）
- Agent 设置最大步数、单任务 token 上限，防止成本失控

### 3.6 工程与部署优化
- 批处理（Batch）非实时请求，单价更低
- 私有化/自托管开源模型应对稳定高负载（量大时边际成本低）
- 弹性伸缩、闲时任务调度
- 选择性价比模型（如 DeepSeek 等低成本开源方案）并保持多供应商可切换

## 四、成本监控体系（先能看见，才能省）

| 看板 | 内容 |
|------|------|
| 总成本趋势 | 日/周/月 token 与费用，环比、预算对比 |
| 分摊视图 | 按功能、模型、用户/租户、渠道分摊 |
| 单客成本 | 每个付费用户的服务成本与毛利 |
| 效率指标 | 缓存命中率、模型路由占比、平均单次 token |
| 异常告警 | 成本突增、超预算、单用户异常 |

## 五、成本—效果联合决策

不能为省钱牺牲核心体验，每次优化都要在评测集 + 线上验证：

| 手段 | 成本影响 | 效果风险 | 验证方式 |
|------|----------|----------|----------|
| 模型路由 | 大幅下降 | 升级误判会降效果 | 评测集 + 灰度对比 |
| 缓存 | 下降 | 个性化/时效问题 | 命中率与满意度监控 |
| Prompt 压缩 | 小幅下降 | 丢关键指令 | 回归评测 |
| 上下文筛选 | 中幅下降 | 漏关键信息 | 召回率监控 |
| 换便宜模型 | 大幅下降 | 综合效果下降 | 全量评测对比 |

常用决策指标：**每降低 1% 成本，效果损失多少**；以及单客毛利是否转正。

## 六、商业化联动

- 成本结构直接决定定价（见[定价策略](01_定价策略.md)）：重度用户必须有额度或按量约束
- 企业私有化要把部署与运维成本计入报价
- 免费版额度要基于"单个免费用户最大可承受成本"来设计

## 七、常见误区

| 误区 | 纠正 |
|------|------|
| 只看总账单，不做分摊 | 无法定位成本来自哪个功能/用户 |
| 所有请求都用旗舰模型 | 简单任务路由到小模型 |
| 上下文"宁多勿少" | 精准检索 + 压缩，省 token 且降噪 |
| Agent 无步数/预算上限 | 易死循环、账单失控 |
| 省钱后不测效果 | 每次优化都回归评测 |
| 忽视输出 token | 输出是成本大头，控制长度 |
| 只在出账单后才优化 | 建立实时成本监控 |
