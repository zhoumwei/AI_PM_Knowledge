# SaaS 商业模式

> 所属维度：商业化能力 ｜ 参考分：58

## 一、能力定义

理解 SaaS（Software as a Service，软件即服务）的商业逻辑与经营指标，能为 AI 产品设计**可规模化、可持续、可扩展**的商业模式，并判断业务是否健康。

## 二、SaaS 的本质特征

| 特征 | 说明 |
|------|------|
| 订阅制 | 客户按年/月持续付费，而非一次性买断 |
| 经常性收入 | 收入是"持续流"（ARR/MRR），可预测 |
| 客户成功导向 | 客户持续用出价值才会续费 |
| 规模化 | 边际交付成本低，一套产品服务众多客户 |
| 快速迭代 | 云端统一升级，所有客户同步 |

## 三、SaaS 核心经营指标（PM 必懂）

| 指标 | 全称 | 含义 |
|------|------|------|
| MRR/ARR | 月/年度经常性收入 | SaaS 收入的核心 |
| Churn | 流失率 | 客户或收入流失（越低越好）|
| NRR | 净收入留存率 | 老客户今年收入/去年收入，含增购流失，健康线 >100% |
| CAC | 获客成本 | 获取一个客户的销售+市场成本 |
| LTV/CLV | 客户生命周期价值 | 一个客户长期贡献的利润 |
| LTV/CAC | 获客效率 | 健康参考 ≥ 3 |
| CAC Payback | 回本周期 | 多久赚回获客成本，参考 < 12-18 月 |
| ARPA/ARPU | 每账户/每用户平均收入 | 客单价水平 |
| 毛利率 | (收入−服务成本)/收入 | 优秀 SaaS 70%+ |

**SaaS 的增长飞轮**：获客 → 客户成功 → 高留存/续费 → 增购（NRR>100%）→ 更多收入投入获客。

## 四、SaaS 常见收费结构

- **按席位（Per Seat）**：每人每月，传统 SaaS 主流
- **按用量（Usage）**：按调用/token/存储，AI 产品常见
- **分层套餐（Tiered）**：免费/专业/企业，功能与额度递增
- **混合（Seat + Usage + Tier）**：AI SaaS 越来越普遍
- **平台/生态分成**：在应用市场分发，按比例分成

## 五、AI SaaS 的特殊挑战（重点）

传统 SaaS 毛利率高（软件边际成本近零），但 AI SaaS 有持续的推理成本，商业模式更复杂：

| 挑战 | 说明 | 应对 |
|------|------|------|
| COGS 含推理成本 | 用得越多成本越高，毛利承压 | 用量计费/额度 + 成本控制 |
| 成本波动 | 模型用量、厂商定价变化 | 多供应商、模型路由、合同条款 |
| 重度用户负毛利 | 订阅费覆盖不住其推理成本 | 公平使用 + 超量按量 + 升档 |
| 价值证明压力 | AI 效果要可量化才好续费 | 效果报告、ROI 度量 |
| 私有化诉求 | 大客户要数据不出域 | 企业版/VPC/私有化单独定价 |
| 同质化与价格战 | "套壳"门槛低 | 数据、场景、工作流、生态壁垒 |

## 六、部署模式：SaaS vs 私有化

| 维度 | 公有云 SaaS | 私有化/混合 |
|------|-------------|-------------|
| 交付 | 快、标准化 | 慢、定制重 |
| 成本 | 厂商承担基础设施 | 客户承担环境，一次性收入高 |
| 数据 | 出域到云 | 客户可控（金融/政务刚需）|
| 迭代 | 统一快速升级 | 版本维护成本高 |
| 客单价 | 较低、走量 | 高、大客户 |
| 适合 | 中小客户、通用场景 | 大型/强监管客户 |

很多 AI 企业（尤其 toB、运维、金融）采用**"标准版 SaaS 走量 + 企业私有化拿大单"**双轨。

## 七、客户分层与市场路径

| 市场 | 客户 | 销售模式 | 特点 |
|------|------|----------|------|
| PLG（产品驱动） | 个人/小团队 | 自助注册，无销售介入 | 低客单、快转化、产品即增长 |
| SMB | 中小企业 | 轻销售/线上 | 中等客单 |
| Enterprise | 大客户 | 直销 + POC + 长周期 | 高客单、重交付、强关系 |

AI 产品常以 PLG 让用户自助体验价值，再由销售承接组织级扩展（Land and Expand）。

## 八、构建 AI SaaS 壁垒（避免陷入价格战）

单纯调用通用模型没有壁垒。可持续的壁垒来自：
1. **专有数据/知识**：私域数据、标注、反馈飞轮（用的人越多数据越好）
2. **场景与工作流深度**：嵌入关键业务流程，替换成本高
3. **系统集成与生态**：深度对接客户现有系统、进入平台市场
4. **品牌与信任**：稳定、安全、合规（toB 尤其重要）
5. **成本与工程效率**：同样效果成本更低，就是利润优势
6. **合规与私有化能力**：进入强监管行业的门票

## 九、商业模式演进路线（参考）

```
免费/开源引流 → 订阅制（分层）→ 按量计费（API/用量）
   → 企业版/私有化（大单）→ 平台生态/分成 → 数据与网络效应壁垒
```
不同阶段重点：早期验证价值与 PMF（产品市场契合）→ 中期提效留存与单位经济 → 后期规模化与生态。

## 十、判断商业模式健康的自检

- [ ] 单客毛利是否为正？重度用户会不会亏损？
- [ ] LTV/CAC ≥ 3？回本周期多长？
- [ ] NRR 是否 > 100%？Churn 在什么水平？
- [ ] 推理成本占收入比例是否可控？
- [ ] 收入是经常性的还是一次性项目？
- [ ] 除了"调用模型"，我的壁垒是什么？
- [ ] 私有化需求如何定价才不亏本？

## 十一、常见误区

| 误区 | 纠正 |
|------|------|
| 把传统 SaaS 高毛利想当然套用到 AI | 推理成本必须计入 COGS |
| 只看签约额，不看续费与 NRR | 经常性收入才是 SaaS 本质 |
| 重度用户无约束使用 | 额度+超量+升档 |
| 靠套通用模型拼价格 | 建数据/场景/集成壁垒 |
| 私有化项目按标准 SaaS 报价 | 覆盖部署运维与定制成本 |
| 过早追求大客户而牺牲 PLG | 匹配产品成熟度选择路径 |

## 十二、自测题

1. 用 ARR、Churn、NRR、LTV/CAC 描述你的业务（或假设产品）。
2. 你的 AI SaaS 毛利率受哪些推理成本影响？如何改善？
3. SaaS 和私有化两种模式，你会如何为不同客户设计？
4. 除了调用通用大模型，你产品的可持续壁垒是什么？
5. 画出产品未来 3 年的商业模式演进路线。
