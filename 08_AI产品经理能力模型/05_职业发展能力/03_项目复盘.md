# 项目复盘

> 所属维度：职业发展能力 ｜ 参考分：70

## 一、能力定义

项目复盘是在项目（或关键阶段）结束后，**系统性回顾目标、过程、结果与偏差，提炼可复用经验和可改进动作**的能力。

经历本身不等于经验——同样的错误有人犯一次就成长，有人反复犯。差别就在于是否复盘、复盘是否深刻。

## 二、为什么复盘重要

- 把一次性的项目经历，转化为可迁移的方法论
- AI 产品不确定性高、坑多，复盘能让团队和个人少走弯路
- 复盘沉淀是作品集、面试故事、简历成果的素材来源
- 帮助客观认识自己的能力长短板

## 三、复盘的经典框架

### 3.1 GRAI 四步法
| 步骤 | 回答 |
|------|------|
| Goal 回顾目标 | 当初的目标是什么？（量化） |
| Result 评估结果 | 实际发生了什么？（对照目标，用数据） |
| Analysis 分析原因 | 为什么有差异？成功/失败的根本原因 |
| Insight 总结规律 | 哪些可复用？哪些要改进？具体行动是什么 |

### 3.2 What / So What / Now What
- What：发生了什么（事实、数据）
- So What：这意味着什么（洞察、规律）
- Now What：接下来怎么做（行动）

### 3.3 5 Whys（追根因）
对问题连续追问"为什么"，穿透表象到根本原因，避免停留在"运气不好/配合不畅"。

## 四、复盘的维度（AI 项目特别版）

除常规的进度、质量、协作外，AI 项目要额外复盘：

| 维度 | 复盘问题 |
|------|----------|
| 需求与场景 | AI 解决的是不是真问题？有没有过度使用 AI？ |
| 模型效果 | 最终指标 vs 预期？差距来自数据/模型/Prompt/检索哪一环？ |
| 数据 | 数据质量与规模是否如预期？标注有什么坑？ |
| Prompt/方案 | 哪些迭代最有效？版本管理是否规范？ |
| RAG/Agent | 召回率/工具调用/人机边界实际表现如何？ |
| 评估 | 评测集是否有代表性？离线与在线是否一致？ |
| 成本 | token 成本是否超预期？哪些优化最有效？ |
| 效果 vs 业务 | 模型提升是否真的带来业务价值？ |
| 协作 | PM/算法/工程/数据的协作接口哪里不顺？ |
| 风险与安全 | 幻觉、越权、高危操作是否暴露问题？ |

## 五、复盘的正确姿势

1. **及时**：项目结束后 1-2 周内做，记忆还新鲜
2. **对事不对人**：聚焦流程与决策，不搞追责批斗，否则听不到真话
3. **基于事实与数据**：少用"感觉"，多用指标、日志、时间线
4. **区分可控与不可控**：聚焦下次能改变的因素
5. **成功也要复盘**：搞清楚是能力还是运气，才能复制成功
6. **产出行动项**：每条经验要落到"谁、做什么、什么时候"，否则等于白复盘
7. **沉淀归档**：结论写入知识库/规范，让他人和未来的自己能查到

## 六、复盘报告模板

```markdown

- 背景/目标/周期/我的角色

## 二、目标 vs 结果
| 目标 | 实际 | 达成 |
|------|------|------|
| Top-3 召回率 ≥85% | 83% | 接近 |
| MTTR 降 50% | 降 41% | 部分 |

## 三、关键过程时间线
（重要决策与事件）

## 四、做对了什么（可复制）
1. …（说明为什么有效）

## 五、问题与根因（5 Whys）

## 六、AI 专项复盘

## 七、经验沉淀（方法论）
- …

## 八、行动计划
| 行动 | 负责人 | 时间 |
|------|--------|------|
```

## 七、常见误区

| 误区 | 纠正 |
|------|------|
| 复盘变追责大会 | 对事不对人，营造安全感 |
| 只复盘失败，不总结成功 | 成功经验同样要固化 |
| 归因于外部/运气 | 深挖可控因素 |
| 结论是"以后注意" | 必须有具体可执行行动项 |
| 复盘完就归档没人看 | 沉淀进规范，指导下个项目 |
| 只凭记忆不看数据 | 用指标和事实说话 |
| 拖延到几个月后 | 趁热打铁 |

## 八、把复盘转化为成长闭环

```
项目实践 → 复盘（GRAI）→ 方法论沉淀（知识库/作品集）
   → 更新简历/作品集 → 指导下一个项目 → 再复盘
```
本知识库本身就是一种复盘沉淀——把项目中的通用经验（如 A/B 测试方案、权限设计、能力模型）文档化。

## 九、自测题

1. 你最近一个项目复盘了吗？目标与结果的差距及根因是什么？
2. 用 5 Whys 分析过一个线上问题吗？根因落在哪一层？
3. 你复盘出的经验，有几条真正变成了后续项目的行动？
4. AI 项目中"离线好、在线差"，你会如何复盘原因？
5. 你最近一次"成功"复盘出了哪些可复制的做法？
