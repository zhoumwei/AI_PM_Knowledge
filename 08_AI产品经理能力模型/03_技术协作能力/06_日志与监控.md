# 日志与监控

> 所属维度：技术协作能力 ｜ 参考分：66

## 一、能力定义

理解系统**可观测性（Observability）**体系，能看懂监控大盘、读懂日志与链路、定义 AI 产品需要监控的指标和告警，从而在故障发生时快速定位、在日常中度量产品健康度。

## 二、可观测性三大支柱

| 支柱 | 回答 | 典型工具 |
|------|------|----------|
| Metrics（指标） | 系统"现在怎么样"（数值趋势） | Prometheus、Grafana |
| Logging（日志） | 出问题时"发生了什么"（明细记录） | ELK、Loki |
| Tracing（链路追踪） | 请求"经过了哪些服务、卡在哪" | Jaeger、Zipkin、SkyWalking |

三者关系：Metrics 发现异常 → Tracing 定位到哪个服务/环节 → Logging 查明具体原因。

## 三、Metrics（指标监控）

### 3.1 四类核心指标
- **计数器（Counter）**：只增不减，如请求总数、错误总数
- **仪表盘（Gauge）**：可增可减的瞬时值，如 CPU、内存、在线人数
- **直方图（Histogram）**：值的分布，如请求延迟分布
- **摘要（Summary）**：分位数，如 P95、P99 延迟

### 3.2 PM 必须懂的百分位
- P50：一半请求快于这个值（整体水平）
- P95：95% 请求快于它（衡量大多数用户体验）
- P99：关注最慢的那批（长尾问题）
- 不能只看平均值——平均会掩盖长尾卡顿

### 3.3 黄金指标（Google SRE 四金标）
| 指标 | 含义 |
|------|------|
| 延迟 Latency | 请求耗时（区分成功/失败） |
| 流量 Traffic | QPS、并发量 |
| 错误 Errors | 错误率、非 2xx 比例 |
| 饱和度 Saturation | 资源还能撑多久（CPU/内存/队列） |

## 四、Logging（日志）

### 4.1 日志类型
- 应用日志、访问日志、错误日志、审计日志（谁在何时做了什么）
- 级别：DEBUG < INFO < WARN < ERROR < FATAL

### 4.2 好日志的要素
时间戳、级别、服务/模块、请求 ID（traceId，串联一次请求的所有日志）、关键上下文、明确的信息。

### 4.3 ELK 是什么
Elasticsearch（存储检索）+ Logstash/Fluentd（采集）+ Kibana（可视化），用于日志聚合与查询。

### 4.4 AI 场景日志重点
- 每次模型调用：模型版本、Prompt 版本、输入/输出 token、耗时、是否命中缓存
- 工具调用：调了什么工具、参数、结果、成败
- 异常：幻觉拦截、内容安全拦截、降级触发、人工转交流

## 五、Tracing（链路追踪）

微服务中一次请求经过多个服务，链路追踪给每个请求一个 traceId，记录经过的每个 span（服务、耗时、状态）。
- 用途：定位"到底卡在检索、模型还是下游工具"
- 在 Agent 场景尤其有用：可视化 Agent 每一步思考与工具调用

## 六、告警（Alerting）

- 基于指标阈值/异常检测触发（如错误率 >5% 持续 5 分钟、P95 > 3s）
- 告警三要素：**何时触发、通知谁、怎么处理（Runbook）**
- 警惕"告警风暴"：要做分级（P1-P3）、聚合、抑制，否则值班人员会麻木

## 七、AI 产品必备监控清单（重点）

### 7.1 业务/效果指标
- AI 回答/归因准确率（在线采样标注）
- Top-K 命中率、无答案率、点踩率
- 建议采纳率、人工接管率
- 幻觉拦截率、安全拦截率

### 7.2 性能指标
- 首 token 延迟、完整响应延迟（P50/P95/P99）
- 工具调用成功率与耗时
- 检索延迟、Rerank 耗时

### 7.3 成本指标
- Token 消耗总量（按功能/用户/模型分摊）
- 单次请求平均成本
- 缓存命中率、模型路由占比
- 日/月成本趋势与预算告警

### 7.4 稳定性
- 模型 API 可用率、超时率、限流（429）次数
- 降级触发次数、错误率

## 八、PM 如何参与监控建设

1. 定义"产品健康度仪表盘"应包含哪些指标（业务+效果+成本）
2. 为每个指标定阈值与告警规则、明确责任人
3. 推动埋点与日志字段覆盖（没有数据就无法监控）
4. 定期（如每周）与团队一起看监控、复盘异常
5. 故障后检查"为什么监控没提前发现"，补齐告警

## 九、常见误区

| 误区 | 纠正 |
|------|------|
| 只看平均延迟 | 关注 P95/P99 长尾 |
| 只监控系统指标，不监控 AI 效果 | 准确率/幻觉/成本必须监控 |
| 只监控不告警，或告警泛滥 | 分级+聚合+明确处理人 |
| 日志没有 traceId | 无法串联一次请求 |
| 成本无监控 | Token 账单可能失控 |
| 告警没有处理手册 | 配 Runbook/SOP |
