# 前后端流程

> 所属维度：技术协作能力 ｜ 参考分：64

## 一、能力定义

理解一次用户操作在**前端、网络、后端、数据库、外部服务之间如何流转**，从而能画时序图、判断性能与体验瓶颈、与前后端高效协作。

## 二、一次完整请求的旅程（核心主线）

以"用户发送一条 AI 消息"为例：

```
① 用户在前端输入、点击发送
② 前端做本地校验（非空、长度）
③ 前端通过 HTTPS 发起请求（带鉴权 Token）
④ 请求到达网关/负载均衡，鉴权、限流、路由
⑤ 后端业务服务处理（查库、组装上下文、调 RAG 检索）
⑥ 后端调用 LLM API（stream=true）
⑦ LLM 逐 token 返回（SSE）→ 后端透传给前端
⑧ 前端边接收边渲染（打字机效果）
⑨ 完成后落库对话记录、埋点上报
```

PM 能把这条链路讲清楚，就具备了与工程团队对话的骨架。

## 三、前端基础（了解即可）

### 3.1 前端做什么
- 页面结构（HTML）、样式（CSS）、交互逻辑（JavaScript）
- 主流框架：React、Vue（组件化、状态驱动）
- 职责：展示数据、捕获交互、表单校验、调用后端、管理页面状态

### 3.2 PM 相关概念
- **渲染**：数据变成画面（服务端渲染 SSR / 客户端渲染 CSR）
- **状态管理**：登录态、加载态、表单数据等
- **路由**：页面间跳转与 URL 对应
- **跨域（CORS）**：浏览器安全策略，前后端不同域时需后端配置
- **本地存储**：Cookie / localStorage / SessionStorage（如记住设置、Token）

## 四、后端基础

### 4.1 后端做什么
业务逻辑、鉴权、数据读写、调用其他服务/模型、缓存、消息队列、定时任务。

### 4.2 PM 相关概念
- **同步 vs 异步**：
  - 同步：请求一直等结果（适合快操作）
  - 异步：先返回"已受理"，后台处理完再通知（适合耗时任务，如生成报告、批量任务）
- **缓存（Redis）**：把热点结果暂存，减少重复计算/调用（如相同 query 的 LLM 结果缓存）
- **消息队列**：削峰、解耦、异步任务排队
- **微服务**：系统拆成多个小服务（告警服务、检索服务、Agent 服务…）

## 五、网络与协议（够用）

| 概念 | PM 需要知道 |
|------|-------------|
| HTTP/HTTPS | 浏览器与后端通信协议；S 表示加密 |
| 请求/响应 | 一问一答的基本模型 |
| SSE | 服务端单向持续推送，适合 AI 流式输出 |
| WebSocket | 双向长连接，适合实时聊天、协同编辑 |
| 状态码 | 2xx 成功 / 4xx 客户端错 / 5xx 服务端错 |
| 延迟构成 | DNS + 建连 + 网络传输 + 服务处理 + 模型生成 |

## 六、部署与交付（了解）

- **CI/CD**：持续集成/持续部署，代码提交后自动测试、发布
- **环境**：开发（dev）→ 测试（test）→ 预发（staging）→ 生产（prod）
- **灰度发布**：先放少量流量验证
- **回滚**：出问题快速退回旧版本
- **容器（Docker）/编排（K8s）**：应用打包与弹性伸缩（听过即可）

## 七、AI 产品的前后端特殊关注点

### 7.1 流式体验
- 前端要处理 SSE 分片、拼接、中断、"停止生成"
- 首 token 时间是关键体验指标（不是总时长）
- 断流/超时的重试与兜底

### 7.2 长任务
- 深度归因、批量分析耗时长 → 异步任务 + 进度反馈 + 完成通知

### 7.3 状态丰富
- 输入中、模型思考中、生成中、可中断、失败重试——状态机复杂，要与前端逐一对齐

### 7.4 安全
- 密钥只在后端，绝不暴露到前端
- 前端校验只是体验，后端必须再校验（防绕过）

## 八、PM 必备产出：时序图

针对核心链路画"参与者 + 消息时序"，参与者如：用户、前端、网关、后端、RAG、LLM。用于评审对齐、定位职责与性能点。

简单文本版示例：
```
用户 → 前端：发送消息
前端 → 后端：POST /chat（stream）
后端 → 检索服务：取相关知识
检索服务 → 后端：Top-K
后端 → LLM：messages + 上下文（stream）
LLM → 后端 → 前端：token 流（SSE）
前端 → 用户：逐字展示
```

## 九、常见误区

| 误区 | 纠正 |
|------|------|
| 认为所有操作都"立刻返回" | 耗时任务应异步+进度 |
| 只关注总时长，忽视首 token | 流式体验看首响 |
| 前端做了校验后端就不做 | 后端必须二次校验 |
| 密钥/复杂逻辑放前端 | 不安全，必须在后端 |
| 不画时序图，职责口头约定 | 核心链路必须文档化 |
