# PRD 文档

> 所属维度：基础产品能力 ｜ 参考分：78

## 一、能力定义

PRD（Product Requirement Document，产品需求文档）是把产品方案转化为**研发、设计、测试可执行、可验收**的书面说明。

好 PRD 的标准：**开发看完不用反复问、测试能据此写用例、新人能据此理解业务**。

## 二、PRD 的核心组成

| 模块 | 内容 |
|------|------|
| 修订记录 | 版本、日期、修改人、变更点 |
| 项目概述 | 背景、问题陈述、定位、价值 |
| 目标与指标 | 业务目标、成功标准、非目标 |
| 用户与场景 | 用户画像、使用场景、用户旅程 |
| 功能需求 | 功能架构、功能清单、详细需求（含规则、边界、异常） |
| 非功能需求 | 性能、安全、兼容性、可用性 |
| 数据需求 | 埋点、指标口径、数据流转 |
| 依赖与风险 | 上下游依赖、风险与对策 |
| 排期与里程碑 | 阶段划分、上线计划 |
| 附录 | 术语、原型链接、参考文档 |

## 三、详细需求的书写要素

每个功能点至少写清：

1. **用户故事**：作为谁，希望做什么，以便什么
2. **业务规则**：判定条件、计算逻辑、约束（用决策表/状态机表达复杂逻辑）
3. **正常流程**：主路径（主流程）
4. **异常流程**：失败、超时、空数据、无权限等分支
5. **边界条件**：极值、并发、字符上限、分页
6. **交互说明**：触发、反馈、loading、成功/失败提示
7. **验收标准**：可测试的 Given-When-Then

**Given-When-Then 示例**：
> Given 用户对高危操作无审批权限，When 点击"执行"，Then 按钮置灰并提示"需主管审批"。

### 用状态机描述复杂对象
如工单状态：待处理 → 排查中 → 已归因 → 待确认 → 修复中 → 已关闭 / 已挂起。明确每个状态的进入条件、可执行动作、流转目标。

## 四、AI PRD 的特有章节（重点）

AI 产品 PRD 必须在传统 PRD 基础上补充：

### 4.1 模型相关
- **模型选型**：主模型 + 备选（含私有化方案）及选型理由
- **输入输出规范**：输入数据结构、输出 schema（建议强制 JSON）
- **Prompt 设计**：System Prompt 模板、SOP 约束、Few-Shot 示例、版本管理
- **知识库/RAG**：数据来源、分块策略、召回 top_k、Rerank、更新机制

### 4.2 效果与评估
- 效果指标门槛：Top-1 准确率、Top-3 召回率、证据支撑率
- 评测数据集：规模、标注规范、更新机制
- 灰度与回滚：模型/Prompt 版本如何灰度、如何回退

### 4.3 安全与边界
- 自动化层级（L1-L5）：本期做到哪一层
- 高危操作清单与审批流（Human-in-the-loop）
- 幻觉兜底：置信度阈值、低置信度如何降级
- 数据脱敏与权限过滤

### 4.4 AI 特有交互状态
加载中、流式输出、生成中断、无结果、低置信度提示、引用来源展示、重新生成、点踩纠错。

## 五、写作原则

1. **一页纸摘要**：文档开头放 TL;DR，照顾没时间读全文的评审者。
2. **图文结合**：流程图讲主路径、状态机讲对象、时序图讲系统交互、表格讲规则。
3. **无歧义**：避免"尽快""支持""等"等模糊词，改为具体数值与枚举。
4. **可验收**：每条需求都能转化为测试用例。
5. **单一事实源**：规则只在一处定义，其他地方引用，避免多处不一致。
6. **维护更新**：需求变更同步更新 PRD 与修订记录。

## 六、评审流程

```
PM 自查（研发/测试视角）→ 内部预审（产品组）→ 正式评审
   → 收集疑问修订 → 基线冻结 → 变更走变更流程
```

自查清单：
- 每个功能的异常分支都写了吗？
- 所有"支持/尽快"都替换成具体定义了吗？
- 测试能据此写用例吗？
- 埋点和指标口径定义了吗？
- AI 效果门槛与兜底写了吗？

## 七、常见误区

| 误区 | 后果 |
|------|------|
| 只写正常流程，不写异常 | 研发临场拍脑袋，线上出事故 |
| PRD 写完不更新 | 文档与实际系统脱节 |
| 用大段文字描述复杂逻辑 | 理解偏差；应用图/表 |
| AI 功能不写效果指标 | 无法验收、上线效果无标准 |
| 只写功能不写埋点 | 上线后无法度量 |
| 需求评审变成"现场讲解会" | 应提前发文档，评审只过争议点 |

## 九、自测题

1. 你最近一份 PRD，异常分支覆盖了多少种？
2. 把一段含"尽快""支持"的需求描述改写为无歧义版本。
3. 你的 AI 功能在 PRD 里写了哪些效果指标与兜底策略？
4. 评审后，研发还会来问你的问题主要集中在哪几类？如何提前消除？
