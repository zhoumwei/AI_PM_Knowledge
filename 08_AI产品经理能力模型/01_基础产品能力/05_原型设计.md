# 原型设计

> 所属维度：基础产品能力 ｜ 参考分：80

## 一、能力定义

原型设计是用可视化方式表达产品的**信息架构、页面布局、交互流程与状态变化**，用于快速验证想法、对齐团队、降低开发返工。

原型不是"画得像不像成品"，而是"能否表达清楚产品逻辑"。

## 二、原型的保真层级

| 层级 | 特征 | 用途 | 工具 |
|------|------|------|------|
| 低保真（线框图） | 黑白方框、无样式 | 早期探索结构与流程 | 纸笔、Balsamiq |
| 中保真 | 布局完整、基础组件 | 需求评审、交互对齐 | Figma/Axure |
| 高保真 | 视觉/动效接近成品 | 视觉走查、用户测试、演示 | Figma/Sketch |
| 可交互原型 | 页面可点击跳转 | 可用性测试、Demo | Figma Prototype |

原则：**用最低成本验证当前最大的不确定性**。结构没定时不要抠颜色。

## 三、设计的三层结构

1. **信息架构（IA）**：内容如何组织、导航如何分层（画站点地图/树状图）
2. **流程设计**：用户完成任务的步骤（画任务流/流程图）
3. **界面设计**：单页布局与交互细节（画线框/高保真）

顺序自上而下，避免一上来就画单页。

## 四、交互设计要点

### 4.1 覆盖完整状态
每个页面/组件要考虑：默认态、加载态、空态、错误态、成功态、无权限态、极端数据态（超长文本、大量数据）。

### 4.2 交互说明要写清
- 触发方式（点击/悬停/输入）
- 系统反馈（loading、toast、跳转）
- 边界规则（最少/最多输入、防重复提交）
- 异常处理（断网、超时、失败重试）

### 4.3 常用设计原则
- **一致性**：同类操作交互一致
- **可见性**：关键动作一眼可见
- **反馈**：每个操作都要有响应
- **容错**：危险操作可撤销/二次确认
- **效率**：为高频用户提供快捷键/批量操作

## 五、AI 产品的原型设计（重点）

AI 产品相比传统产品多了大量"非确定性"状态，必须在原型中覆盖：

### 5.1 流式生成体验
- 打字机式逐字输出（非长时间空白等待）
- 生成中可"停止"
- 首 token 等待时的骨架屏/思考动画

### 5.2 结果的不确定性
- 低置信度提示："AI 对该结论把握不大，建议核实"
- 提供多个候选（如根因 Top-3）而非唯一答案
- 展示信息来源/引用（RAG 可解释性）

### 5.3 纠错与反馈
- 点踩/点赞、重新生成、"答案有误"具体原因
- 用户可编辑/补充 AI 输出

### 5.4 人机协同界面
- 高危操作二次确认弹窗，清楚展示"AI 将做什么、影响范围"
- 自动执行前的预览、执行后的结果回执
- Agent 执行过程可见（"正在查询日志…正在分析变更…"），建立信任

### 5.5 异常与降级
- AI 超时/不可用时的降级文案与替代路径
- 内容违规/无法回答时的安全兜底
- Token/额度耗尽提示

## 六、主流工具

| 工具 | 特点 | 适合 |
|------|------|------|
| Figma | 云端协作、组件库、生态强 | 主流首选 |
| Axure RP | 逻辑/条件强大、文档化 | 复杂 B 端 |
| Sketch | macOS、轻量 | 视觉设计 |
| 即时设计/MasterGo | 国产、中文友好 | 国内团队 |
| draw.io / ProcessOn | 流程图、架构图 | 流程表达 |

设计系统：善用组件库（Ant Design、Material、自有 Design System）保持一致性和效率。

## 七、实操流程

```
梳理用户任务 → 画信息架构 → 画任务主流程 → 低保真线框
   → 内部快速过一遍 → 补全异常/AI 状态 → 高保真 + 交互
   → 标注交付研发 → 设计走查
```

## 八、常见误区

| 误区 | 纠正 |
|------|------|
| 一上来就画高保真 | 先定结构和流程 |
| 只画"理想界面" | 必画空/错/加载/极端态 |
| AI 输出画成"瞬间出结果" | 表达流式过程与等待反馈 |
| 只给唯一答案，不表达不确定性 | 多候选 + 置信度 + 来源 |
| 缺少交互说明，靠口头讲 | 标注清楚规则与反馈 |
| 忽视高危操作确认设计 | 明确人机协同交互 |

## 九、自测题

1. 你的原型覆盖了几种 AI 特有状态（流式、低置信度、引用、降级）？
2. 拿你的原型给没参与需求的人看，他能独立完成核心任务吗？
3. 你的列表页画了"空态"和"1000 条数据态"吗？
4. Agent 自动执行的过程，在界面上如何让用户"看得见、可干预"？
