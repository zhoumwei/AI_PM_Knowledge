# 项目管理

> 所属维度：基础产品能力 ｜ 参考分：75

## 一、能力定义

项目管理是围绕**时间、质量、成本、范围**四大目标，组织团队把产品方案按计划交付的能力，包括计划制定、进度跟踪、风险管控、跨团队协作与干系人管理。

产品经理通常不是名义上的 PM（项目经理），但对结果负有实际推动责任。

## 二、铁三角与约束

```
            范围（做什么）
              /\
             /  \
     时间 ---/----\--- 成本
            \    /
             \  /
           质量（底层约束）
```

一个变量变化会牵动其他变量：AI 项目中"模型效果不达标"常迫使延期（时间）或砍范围。

## 三、核心方法

### 3.1 敏捷 / Scrum

| 角色/事件 | 说明 |
|-----------|------|
| Product Owner | 产品经理，维护需求优先级（Backlog） |
| Scrum Master | 保障流程、移除障碍 |
| Sprint | 固定迭代周期（通常 2 周） |
| 每日站会 | 昨天做了什么/今天做什么/有什么阻碍 |
| 评审会 | 演示可交付增量 |
| 回顾会 | 复盘流程改进 |

### 3.2 需求管理
- Backlog 分级（Epic → Feature → Story → Task）
- 每个 Story 符合 INVEST 原则（Independent/Negotiable/Valuable/Estimable/Small/Testable）
- 估算：故事点（斐波那契数列）或理想人日

### 3.3 里程碑与甘特图
- 关键里程碑：需求冻结、设计定稿、开发完成、提测、灰度、全量
- 识别**关键路径**（决定项目最短工期的任务链）

### 3.4 风险管理
风险登记表：风险描述、概率、影响、等级、应对策略（规避/转移/减轻/接受）、负责人、状态。

## 四、AI 项目的特殊性（重点）

AI 项目比传统软件项目不确定性高得多，传统"需求→开发→测试"模式不完全适用：

| 差异点 | 传统项目 | AI 项目 | 管理应对 |
|--------|----------|---------|----------|
| 效果确定性 | 做出来就能用 | 指标可能不达标 | 先做 PoC/评测再立项 |
| 工期 | 可较准估算 | 调优周期不可控 | 里程碑留 buffer，设探索期 |
| 数据依赖 | 弱 | 强 | 数据准备作为独立前置任务 |
| 验收标准 | 功能有无 | 功能 + 效果指标 | PRD 写死指标门槛 |
| 迭代逻辑 | 功能叠加 | 数据/模型/Prompt 迭代 | 区分工程任务与实验任务 |
| 团队角色 | 前后端 | +算法/数据/标注 | 明确协作接口 |

### AI 项目推荐节奏
```
PoC 验证（1-3 周：数据通不通、模型行不行）
  → 效果基线（达到门槛才继续）
  → MVP 工程化（核心链路 + 人机协同）
  → 灰度评测（在线指标 + 人工标注）
  → 迭代调优 → 全量
```
PoC 未达预设门槛 → 果断止损或转向，这是 AI 项目最重要的"关卡意识"。

## 五、跨团队协作

- **明确接口**：谁在什么时间给什么输入/输出（RACI 矩阵）
- **信息同步**：固定节奏（站会/周报/看板），故障或需求变更即时同步
- **文档先行**：会议结论、技术方案、变更记录书面化
- **向上管理**：让管理者了解进度、风险、需要的支持（报风险要带选项）

### RACI 责任矩阵
- R（Responsible 执行）、A（Accountable 负责）、C（Consulted 咨询）、I（Informed 知会）

## 七、常见误区

| 误区 | 纠正 |
|------|------|
| 没做 PoC 就全量投入 | 先设技术验证关卡 |
| 把模型调优工期拍死 | 用时间盒（timebox）+ 缓冲 |
| 数据准备不当任务 | 数据是 AI 项目关键路径 |
| 只盯进度不盯风险 | 每周更新风险表 |
| 验收只看功能上线 | 同时验收效果指标 |
| 变更无流程 | 走变更评审，评估对铁三角影响 |
| 项目结束不复盘 | 沉淀排期与风险经验 |

## 八、自测题

1. 你最近项目的关键路径是哪条？延期风险最高的环节是什么？
2. 项目里"工程任务"和"模型实验任务"分别是怎么排期的？
3. PoC 未达门槛时，你的止损标准是什么？
4. 你管理的风险表里目前最高等级的风险是什么？应对方案是什么？
